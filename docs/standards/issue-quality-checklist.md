# Issue 质量检查单（issue-quality-checklist）

> 性质：双检的形式检查基料（DR-030）。脚本化部分由 `scripts/issue_lint.sh` 机器卡口（首版两条硬规则：checkbox≥3+[T]/[P] 标注格式）；本单覆盖机器测不了的内容维度。
> 门禁分离：本单与 lint 属流程门禁（CI 独立 check），永不并入 verify.sh。

## A. 建 issue 时（制作人席把关）

- [ ] 字段齐：目标/依赖/规模/DR 摘录（验收锚）/验收点/实施提示（真源 issue-spec.md §1）；
- [ ] 验收 ≥3 条 checkbox，[T] 注 GUT 用例名、[P] 注试玩脚本；
- [ ] 界面类：附状态-视觉映射表行+反馈链路清单引用；
- [ ] DR 清点：本 issue 覆盖的 DR 裁决逐条摘录，无漏译；
- [ ] 不越冻结范围：动 schema/verify 必跑集/DR 裁决本体 → 标 [change] 待双签。

## B. 认领时（实施 agent 自证）

- [ ] 独占认领评论（[claim] agent=… ts=…）+读回验证；
- [ ] 验收点逐条可理解，含糊处先评论问清再动工（禁猜）；
- [ ] S/M：主策划内容审通过记录；L：对抗评审结论链接。

## C. 关 issue / PR 时（code-review 需求轴把关）

- [ ] 自证表逐条引用证据：GUT 用例名+**该用例 passing 输出行**/截图路径/命令输出（禁自然语言复述）；
- [ ] [T] 全勾且证据可验真（grep 用例存在+输出行）；[P] 保持未勾留给试玩；
- [ ] 涉反馈修复：回答"用户原话被哪条新增验收点捕获"（回写复核）；
- [ ] 界面类：状态-视觉映射表已同步更新；
- [ ] verify.sh 全绿证据在案（游戏代码门禁，与流程门禁分立）。
