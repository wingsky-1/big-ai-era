# Issue 规格真源（issue-spec）

> 性质：**内容真源**（DR-030）。gd-issue-pipeline §2.1 模板节改为引用本文件。
> 依据：2026-09-08 全程复盘圆桌 V2.2 裁决；人类制作人主诉"issue 质量太低→实施不可玩"。

## 1. issue 必备字段（缺一不建）

```markdown
## 目标
<一行动词短语>

- 依赖 / 关联：<issue# 或 DR#>；规模：S/M/L
- 决策依据：DR-xxx <裁决句摘录（验收锚）>   ← 只摘录不补写
- 验收点：
  - [ ] [T] <正常路径断言>（GUT 用例名：test_xxx）
  - [ ] [T] <边界/空态/拒绝分支断言>（GUT 用例名：test_xxx）
  - [ ] [T] <可观察终态断言>（GUT 用例名：test_xxx）
  - [ ] [P] <主观体验项>（试玩脚本：docs/playtest/scripts.md#编号）
- 实施提示：<架构稿节/数据表/参考文件路径>
```

## 2. 验收粒度三要素（每功能点 ≥3 条 checkbox）

1. **正常路径**：用户做什么→系统发生什么（"点员工卡→详情面板弹出且工作区该卡高亮"）；
2. **边界/空态/错误路径**：拒绝分支、空数据、非法输入（"0 人发起训练→拒绝且提示"）；
3. **可观察终态**：状态变化必须可见可断言（"指派成功 0.5s 内卡片状态刷新"）。

反例（#30 实测）：验收=「verify 全绿+设计稿评审通过」——零对照目标，实施自由发挥。
正例：同 issue 改写后含 3 条 [T]（各注 GUT 用例名）+1 条 [P]（注试玩脚本）。

## 3. 验收锚写法（DR 立裁时同步产出）

- DR 立裁时直接写**验收句**（"自动周报弹出时 UI 速度键停喂且有常显态"），issue 只摘录不补写——补写即失真源头；
- DR 条目标**验证状态两级**：`已试玩验证` / `仅稿面裁决`。**按实施后补原则**：DR 被实施并通过试玩验证时，才在该 DR 行补标（制作人裁决 2026-09-08，不批量补录存量）。

## 4. 界面类 issue 附加段（强制）

- 附**状态-视觉映射表行**（真源：ui-state-visual-mapping.md，含信标列——信标落地前豁免标注）；
- 附**反馈链路清单**（真源：ui-feedback-checklist.md：即时态/结果态/禁止态/信号断言/刷新断言/竖屏可达）；
- 交互句式：用户做什么→界面出现什么（禁"支持 XX 功能"式无界面描述）。

## 5. 双检分工（过检才可认领）

| 检 | 内容 | 执行者 |
|---|---|---|
| 形式检查 | issue_lint 两条硬规则：checkbox≥3+[T]/[P] 标注格式 | 脚本（机器卡口） |
| 内容审查 | 验收点三要素是否真成立、DR 摘录是否忠实、边界态是否漏 | 主策划席 |
| 对抗评审 | 规格/边界/可实施性攻击 | 独立子代理（**仅 L 规模**；S/M 免，若流程漂移指标劣化回调抽检范围） |

## 6. [P] 项写法

三段式：**步骤脚本**（前置态/操作序列）+**预期感受**（写明可对照的行为表现）+**代理指标**（"10 秒完成首指派"）。主观项禁止伪装成 [T]；[P] 项留给真人试玩勾选，禁止 agent 代跑冒充完成。

## 7. 门禁分离原则（制作人裁决 2026-09-08）

- `verify.sh` = **游戏代码质量门禁**（lint/GUT/模拟），不掺流程检查；
- issue_lint / issue-gate = **CI 独立 check**（PR body 解析+关联 issue 校验），永不并入 verify.sh 必跑集；
- 但红线同等：**无 issue 不合码**（PR body 必须引用 issue，CI issue-gate 校验；分支保护 require issue-gate 由制作人一次性配置）。
