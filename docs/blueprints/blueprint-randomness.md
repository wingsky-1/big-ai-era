# 随机系统蓝图（Blueprint: Randomness）

> 状态：[讨论稿] ｜ 阶段：P0 已具雏形，P1/P2 目标形态如下 ｜ 读取序：README → 本文件

## 一、定位

**玩家视角**：随机是"开盲盒"不是"堵路"——任务可能提前/多奖/小事故，员工状态有好有坏，但所有波动都挂在我能读的规律上（读表胜天）；我知道大概会发生什么、不知道具体哪一周，惊喜与预判并存。

**设计原则**：中频、低烈度、挂读表；确定性优先（同种子可复现、万周模拟可断言）；**任何新随机源都必须先过"供给口径联标"**（防打穿资源供给带与破产率断言）。

## 二、目标形态（终态）

1. **任务事件壳**：任务完成时有概率出现"波动/额外奖励/小事故"（触发率 0.10–0.20/任务、冷却 4–8 周、期望净效果小）；**表现与结算分离**——表现层可提前给区间感，结算层变化受严格上限约束（收入波动 ≤±10%，否决 ±25% 形态）。
2. **员工状态带**：员工有状态（专注/摸鱼/灵感走高），**状态→产出带可读**（看到状态能预判产出区间）；**周粒度更新**（一周掷一次、周内状态稳定），不做逐 tick 掷骰（性能与可读双优）。
3. **灵感揭示时机**：灵感只决定"何时揭示可研节点"，不决定结果成败（pitch="揭示时机随机、结果成败不随机"）。
4. **确定性仪式位**：年度/季度大赏、竞对发版为**确定性时间线**（零 RNG），随机源不与仪式撞周堆叠。
5. **随机源登记制**：每个新随机源=一个可命名、可计数、可断言的分域（种子可复现、计数入档）；不允许"顺手加个 rand()"。

## 三、GDS 可复用语言

- **灵感=开发期盲盒**：GDS 开发中灵感事件影响质量；本作任务事件壳承接；
- **读表胜天**：组合表公开、波动有区间提示，"可预判=可针对=赢了爽"；
- **频率低、含义大**：随机不作用于固定时长本身（时长稳定可预判），只做增量扰动。

## 四、阶段路径

### P0 骨架：事件调味 + 灵感翻雾
- 内容：事件卡（通知/决策）+ 灵感触发翻雾 + 竞对 ± 扰动——三处有界随机，全部周结点消费、可断言。
- 判定 [P]：随机给我惊喜但不让我觉得"被耍"；同种子重放行为一致。

### P1 深化：任务波动 + 员工状态带
- 内容：任务事件壳（波动/额外奖励/小事故，结算层上限收口 ≤±10%）；员工状态带（周粒度、产出带可读）；事件壳与状态带**共用一个随机分域或显式声明互不稀释**（防 pity 类保底被稀释）。
- 判定 [P]：我能说"他这周状态不好，出活会慢一点"；波动让我调整计划而不是推倒计划。

### P2 长线：随机密度与可读性成熟
- 内容：随机事件/波动的密度与含义随阶段成熟（后期随机=更有分量的抉择）；收集品掉落随机（低概率、高含义、不堵路）；同 seed 可复述=运气可讨论（单局内）。
- 判定 [P]：单局后期随机给我的仍是"开盲盒"而非"赌运气"；波动幅度与含义随阶段合理放大。（不做多周目种子继承。）

## 五、系统联动

- 时间（事件/灵感不撞周、节拍错峰）→ 密度闸
- 经济（波动叠加的尾部风险）→ **必须加最坏组合断言**（任务波动+员工状态+竞对扰动同向叠加的下限断言）
- 员工（状态带）→ 随机挂人
- 科技树（灵感揭示）→ 随机挂树
- 模型（训练 checkpoint 卡点=确定性事件，不掷骰）→ 等待段钩子

## 六、开放问题

1. 多随机源（事件/灵感/任务壳/状态带）是否共享计数分域或各自独立——以"保底不被稀释"为判据；
2. 状态带对产出的影响系数上限（建议与任务波动同量级，防三源叠加破下限断言）。
