# UI/UX · 交互 · 可视化蓝图（Blueprint: UI/UX）

> 状态：[讨论稿] ｜ 阶段：P0 已具形态，P1/P2 目标形态如下 ｜ 读取序：README → 本文件

## 一、定位

**玩家视角**：一眼看懂实验室在发生什么——**任务进度在推进（最显眼）、一切"数值在涨"都可见（次显眼）：员工属性变化、论文/模型/芯片的 n 维质量评分变化、钱在进出**；对手不占主界面，只在关键时刻现身（"回头一看被追上了"的惊觉感）；我的每个操作在 0.5 秒内有反馈；竖屏不挤、横屏不空；动画有预算，仪式有排面。

**设计原则**：**重点感知排序=任务进度 > 属性与产物 n 维评分变化（员工属性 + 论文/模型/芯片质量维度）> 资源与周报 > 竞对**（最能刺激玩家感官的放最显眼，竞对放最不显眼）；"数值在涨"是核心感官刺激——员工变强、模型出分、论文发表、芯片升档都要有可见的数值跳动；因果可见（决策→结果的链路放大镜）；反馈链路短（点击-结果即时）；竖屏折叠心智权重倒序（工作区永不折叠）；可视化=只读展示（禁交互画布精神）；动画三级预算（L3 全屏一局 ≤3 次=两次晋升+终局，其余仪式走 L2 金框头条）。

## 二、目标形态（终态）

1. **Dashboard 四主区（重点感知排序）**：工作区（任务/训练实体卡，**进度条最显眼**，永不折叠）/ 员工区（实体卡+属性变化动画）/ 资源栏（刻级跳动）/ Dock 三键；**竞对不常驻主界面**（仅轻量入口：周报头条/悬停/关键时刻弹层可查 SOTA 榜与差距）；迷雾面板=列表+1-hop 微图+"???"行+域计数。
2. **任务进度=第一视觉**：任务/训练进度条主视觉放大（周内刻级进度+预计结账 Wx+完成瞬间的弹跳反馈）——最能刺激感官的变化放最显眼；进度变化有刻级动画（轻量，非每刻结算动画）。
3. **属性与产物 n 维评分变化=第二视觉**：①员工卡属性/状态变化有可见动画（升级闪烁/状态色带/观察文本切换）；②**论文/模型/芯片出分（发布）瞬间，n 维质量评分逐条跳动揭晓**（创新/严谨/影响/复现；推理/知识/对话/速度/成本；算力/能效/成本/稳定性）——"数值在涨"的多维可视化，最能刺激感官；③n 维画像可随时回看（模型卡/论文卡/芯片卡翻开看雷达图或条形图）。
4. **结果曲线可视化**：SOTA 分数对决图（玩家 vs 对手时间线曲线，破纪录点打星——查看时展开，不占主位）；现金流曲线（周结点连线+破产/警告线常显横线）——经济可见化+守卫张力的可视化闭环；**L2 出数、只读不交互**。
5. **周报收敛**：自动弹=显著变化周（名次/差距/红灯/符号翻转/资金显著变化）；平淡周=灰点（无数字无色无音效，点一次本周消失）；4x 下不弹。
6. **周内进度**：任务/训练"预计结账 Wx"+进度区间（无每刻结算动画）；速度暂停常显。
7. **仪式排面**：令牌范围——晋升/终局=L3 全屏（预算 2+1 次）；首次出分命名/破纪录/SOTA 大赏=L2 金框头条（不占 L3 预算）。
8. **竖屏折叠**：资源栏副行折叠、工作区永不折叠；目标卡横向 6 点进度条；员工卡竖屏仅一行+角标。

## 三、GDS 可复用语言

- **全景可视化**：GDS 办公室一切可见（人在走动/设备/进度）；本作"员工/任务/训练实体可见"承接；
- **信息即所见**：GDS 每月结账/进度条/新闻直接看；本作周报+资源栏+曲线的"因果可见"；
- **读表胜天**：GDS 组合表公开；本作对照表（任务×员工×基座）、迷雾域计数等公开可查；
- **仪式反馈**：GDS 大奖颁奖/新机公布；本作晋升/命名/破纪录的排面分级。

## 四、阶段路径

### P0 骨架：四主区 + 弹窗栈 + 竖屏折叠
- 内容：Dashboard 四主区（**任务进度主视觉+员工区**，竞对仅轻量入口）；PanelStack（z0–z3 四层）；迷雾 C 方案；周报双挂载（自动弹 z2/重看 z1）；竖屏折叠；员工卡实体+快速指派；显示分级（低分只显档位标签）。
- 判定 [P]：10 秒内看懂主台在发生什么（**第一眼是任务在推进、人在干活**）；指派 ≤2 击；竖屏不溢出不遮蔽；对手信息"查得到但不压着人"。

### P1 深化：n 维画像 + 曲线可视化 + 观察文本 + 周报收敛
- 内容：**产物 n 维画像可视化**（模型/论文/芯片卡的雷达图或条形图，出分瞬间逐条跳动揭晓；n 维权重公开）；SOTA 对决曲线+现金流曲线（L2 出数、只读，**查看时展开不占主位**）；员工静态观察文本+协作/状态角标+属性变化动画；周报复合谓词自动弹（平淡周灰点）；目标卡横向进度条；常显警报（破产/警告/贷款入口同屏）。
- 判定 [P]：主界面第一视觉=任务进度/"数值在涨"（属性+n 维评分，刺激感官的在前）；出分瞬间 n 维逐条揭晓=想截图的时刻；平淡周不被弹窗打扰；濒死时同屏看到自救入口。
- **重绘预算**：可引入图形/图表绘制库（若自绘成本过高，评估成熟开源方案），曲线与 n 维画像数据 L2 出、L3 只画。

### P2 长线：收集图鉴 + 模型库 + 仪式动效
- 内容：收集图鉴面板（员工相册/论文谱系/模型库，零数值收益最小格起步）；模型卡（命名/曲线/部署状态）；动画动效预算分级执行（单局内完成度叙事）。
- 判定 [P]：打开图鉴有"收藏家"的满足感；终端总览（终局 summary）有"这一局的故事"感；单局内即可集齐/接近集齐（不依赖多周目）。

## 五、系统联动

- 全部系统共用本蓝图的呈现层（员工卡/模型卡/曲线/周报/迷雾/竞对轻量入口/弹窗栈）；
- 契约：L2 出数（呈现层只格式化，不触碰玩法数值）；动画预算表全局唯一（晋升/终局/命名/大赏/破纪录的预算分配见 §二 6）；
- Dock 三键冻结（增键=变更控制）；新面板（模型库/图鉴）注册进 PanelStack 注册表（每次 +1 过命令落点核对）。

## 六、开放问题

1. 曲线可视化落点（主台摘要带 vs 工作区内嵌）与竖屏尺寸适配——原型先行；
2. L2 金框头条的并发优先级（命名/破纪录/大赏/晋升/终局同周时的头条顺序）；
3. **n 维画像的呈现形态**：雷达图 vs 条形图（竖屏尺寸、可读性、动效预算）；出分瞬间逐条跳动揭晓的动效是否占 L2 动画预算；
4. n 维评分在主台常显 vs 详情展开的取舍（若全部常显会挤占"任务进度第一视觉"——建议 n 维变化用轻量角标提示，详情页展开）。
