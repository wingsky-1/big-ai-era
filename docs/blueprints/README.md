# 《大 AI 时代》系统蓝图集（Blueprints）

> 性质：**与当前实现解耦的目标形态设计集**。只回答"这个系统最终应该长什么样、分几步走到"；
> 不绑定任何现有裁决（F1–F9）、数据表键名、代码形态与版本号。版本排期由制作人在本蓝图集产出后单独重排。
> 读取序：README（总纲）→ 按需读单系统蓝图；每份蓝图末尾"系统联动"给出跨系统链接。

## 一、蓝图集定位

1. **目标形态先行**：每份蓝图定义该系统的"终态体验"（玩家语言）+ 达到终态的**阶段路径**（Phase 0→1→2），不提当前实现了什么。
2. **解耦纪律**：蓝图内不出现既有裁决编号、冻结口径、数据文件键名、issue 号；不预设当前代码能复用多少。版本排程前，蓝图只做"方向与阶段"的定稿。
3. **载体独立**：每系统一文档，可单独评审、单独拍板、单独进版本重排；相互依赖通过"系统联动"节显式声明。
4. **数值纪律**：只给形态与占位带（如"~"），具体数值在拍板后由数值席建表收口；禁止在蓝图中锁死数字。

## 二、阶段定义（版本无关的成熟度标尺）

| Phase | 含义 | 判定标准（[P] 试玩语言） |
|---|---|---|
| **P0 骨架** | 系统的最小闭环：能进核心循环、不出戏 | "第一次玩到这一步：我知道这个系统在干什么，且它不影响我继续玩" |
| **P1 深化** | 系统有策略深度：≥2 个真实决策面、与另一系统产生联动 | "同一个选择我会犹豫，且不同选法导致不同走向" |
| **P2 长线** | 系统在单局内深化：收集/仪式节拍/规模升级，有完成度与回头率 | "这一局越到后期越有盼头，收尾时有'值得再来一局'的冲动" |

> 范围裁明（制作人 2026-09-10）：**不做离线玩法；存档读档与多周目暂不考虑**——P2 的"长线"指单局内的深度与完成度，不指跨局继承。版本重排时把 Phase 映射到具体版本号（可一个版本含多系统同 Phase，或单系统跨版本走完 Phase）。

## 四、与版本重排的关系（输入而非结论）

1. 本蓝图集是**方向输入**：制作人据 11 蓝图 + 玩家试玩证据 + 工程约束，重排版本计划（哪些系统进哪个版本、Phase 切在哪个版本）。
2. 蓝图不承诺工作量与先后；跨系统依赖（矩阵中"系统联动"）是版本排程的拓扑约束，排程时优先闭合首循环依赖链。
3. 拍板动作：每份蓝图可独立拍板（接受/修改/推迟）；拍板后进入需求管线（初析→分级→规格化→实施），届时才与实现耦合。

## 五、评审吸收与勘误记录

> 独立对抗评审（2026-09-10，对脱耦前单体稿）已吸收，关键结论：

1. **数值底座三连（必答）**：科技树去 uniform 后 tb 总量变化对出分公式/首达满分周/对手守卫带（L1–L4）的连锁影响 → `blueprint-tech-tree.md` §四 P1 联标推演制 + 开放问题 2；**同批必须做 V6 占比口径复议**。
2. **影响力供给口径**：授权"公开权重+影响力"=新供给源、大赏影响力脉冲、"名气"消耗（点树外第二出口）——全部须过供给真源（唯一来源=任务+事件）修订，至少黄级 → `blueprint-models.md` 开放问题 1 / `blueprint-economy.md` 开放问题 2。
3. **引用勘误（单体稿旧内容，蓝图不承载）**：8 动作实表周次 = 6/12/24/40/54/68/75/82（2 论文+2 涨价+4 发版）；芯片支线/价格战/影响力出口无"已排队"裁决依据（提案级）；图鉴容器批次归 v0.2 第一批；员工观察文本=**静态种子非轮转**（否决项 1 禁文案轮转）；季度大赏=**黄级**（插管线步骤）非绿级。
4. **staff_tick 粒度定稿**：状态带=**周粒度**（周掷一次、周内稳定、状态→产出带可读），不做逐 tick 掷骰（性能与老炮画像双优；保 p 保底不被稀释）→ `blueprint-randomness.md` §四 P1。
5. **动画预算定稿**：L3 全屏一局 ≤3 次=两次晋升+终局；首出分/大赏/破纪录一律 **L2 金框头条级** → `blueprint-ui-ux.md` §二 6。
6. **防伪决策红线**：协作系数/论文域权重之类"公开常数唯一解"须先数值推演（多域 vs 单域期望收益）→ `blueprint-staff.md` 开放问题 2 / `blueprint-papers.md` 开放问题 1。
7. **离线/归来（制作人裁明 2026-09-10）**：**不做离线玩法；存档读档与多周目暂不考虑** → 时间蓝图 P2 已改"节拍丰富+单局完整"；UI/UX 蓝图 P2 已删"回归摘要"；总纲 §二 阶段定义已同步。
8. **竞对位次（制作人裁明 2026-09-10）**：**竞对不常驻主界面**——主界面聚焦任务进度与员工属性变化（最能刺激感官）；对手信息关键时刻显现/可查 → `blueprint-rivals.md` §二6 + `blueprint-ui-ux.md` §一/§二1。
9. **员工规模与槽位（制作人裁明 2026-09-10）**：初始 **4 人**、扩编 **8→12 人**；任务槽 **≤3~4 上限**（防心智负担）→ `blueprint-staff.md` §二1-2/§四。
10. **科技树无排他（制作人裁明 2026-09-10）**：**所有节点可研究可升级**，无互斥路线 → `blueprint-tech-tree.md` §二3。
11. **共生环（制作人裁明 2026-09-10）**：科技树/论文/模型/芯片**你中有我、我中有你**，三角联动升格为四系统共生环 → `blueprint-tech-tree.md` §二6、§六 推演页。
12. **产物 n 维质量评分（制作人裁明 2026-09-10）**：不只员工属性——**论文/模型/芯片各有 n 维质量画像**（论文=创新/严谨/影响/复现；模型=推理/知识/对话/速度/成本；芯片=算力/能效/成本/稳定性），n 维加权合成单值 score（守 SOTA 守卫带），n 维本身可读可决策；"任务进度 + 数值在涨（属性/n 维评分变化）"为 UI 重点感知 → `blueprint-{models,papers,chips,ui-ux}.md`；**n 维三大来源=员工属性 × 科技树定向强化 × 芯片档位画像**（`blueprint-tech-tree.md` 开放问题 5/6 联标守卫带与权重）。

## 六、共生环推演页（目标，非现值）

> 评审必补项（已升格为制作人确认的方向）：论文方向 → 科技树点亮 → 芯片档位 → 模型 → 回收入，须在数值层闭环推演一页：
> 选题域 RP 权重 → 该域 lit 快 → 解锁链（如某节点 lit→高挡位训练开放）→ 更强模型 → 部署/授权收入 → 买更高档 → 更高基座 → 更强模型…
> **目标**：交付一卷"共生环供需推演"（RP/资金/算力如何被四系统循环分配；每步的期望值与方差；破环链的护栏断言）；落点=`blueprint-tech-tree.md` 开放问题 1，随数值稿同批。
