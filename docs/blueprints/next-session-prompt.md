## 五、任务范围（对 11 模块逐一产出四件套）

对以下 11 个模块（逐一处理，一次一个）：新手引导、员工、时间、经济、随机、科技树、竞对、论文、模型、芯片、UI·UX。
每模块产出一份 `<module>-spec.md`，内含四件套：

### A. 交互细节规格（从零设计）
- 每个玩家操作的完整交互链路：入口 → 操作 → 即时反馈 → 结果 → 异常/边界态；
- 输入抽象：仅用虚拟 Action（`action_primary/action_secondary/pause`、方向键=面板焦点导航），**禁具体按键**；
- 四态定义：空态 / 禁用态 / 加载态 / 错误态（含文案与图示）；
- 触屏目标 ≥48px；竖屏 / 横屏两种形态的行为差异表；
- 每步给出 [P] 试玩验收句（"10 秒内…""≤2 击完成…"）。

### B. UI·UX 规格（从零设计）
- 主台布局与弹窗层级（z0–z3 四层 + PanelStack 注册表；Dock 三键冻结）；
- **状态-视觉映射表**（每行：状态 → 视觉呈现 → 动效 → 文案键）——严格按 `ui-state-visual-mapping.md` 格式；
- 重点感知排序落实：任务进度第一视觉、属性/n 维评分变化第二视觉、竞对轻量入口；
- 动画预算纪律：L3 全屏一局 ≤3 次（两次晋升 + 终局）；首出分/破纪录/大赏一律 L2 金框头条；
- 竖屏折叠（工作区永不折叠）、可达性（对比度/字号/色盲友好）。

### C. 文案（从零设计）
- 全部文案规划键名（键名 + 中文文案 + 长度预算：选项 ≤8 / toast ≤20 / 标题 ≤12 / 周报条目 ≤30 / 正文 ≤60）；
- 术语表：复现/SOTA/烧卡/蒲公英权重流出/消融/评测 eval 等，首次出现配触发式一句话提示；
- 考据纪律：微调/LoRA/蒸馏/消融/过桥资金/驻场外包；**反对**"灵光一闪/断电掉半周"式泛化或反常识表述；
- 仪式文案（首次出分命名/晋升/破纪录/大赏）、事件卡文案、周报模板、员工观察句（静态种子，非轮转）；
- 敏感词三层：Unicode 白名单 + 词表 + 防真人近音。

### D. 数值（从零设计）
- 每模块数值表，规划 `src/data/*.json` 键名（**键名可全新设计**，不受现有表约束）；公式引用键名，代码零硬编码；
- 数值给"~占位 → 建议区间 → 护栏断言"三档；
- **蓝图内部一致性对账**（非对旧实现）：①n 维合成公式与单值 score/守卫带一致；②四系统共生环闭环自洽（论文→树→芯片→模型→回投的期望值 + 方差 + 破环链护栏）；③三阶段经济结构自洽（劳务→产品→资本，破产线/警告线/救济与收入曲线配套）；④员工规模（4/8/12）与槽位（≤3~4）与产出曲线配套；
- **n 维评分数值**：维度集、权重、合成公式、三大来源（员工 × 科技树定向强化 × 芯片档位画像）分配、与 SOTA 守卫带/饱和护栏联标；
- **共生环数值闭环**：论文（方向/RP）→ 科技树（点亮）→ 芯片（档位）→ 模型（出分/收入）→ 回投，完整推演一页。

## 七、工作方式与纪律

1. **蓝图=唯一真源**：不读不引用现有实现；蓝图间冲突以 README 总纲为准，仍冲突 → 登记开放问题，不静默二选一。
2. **一次一个模块**：逐个产出、逐个自检（格式合规、键名自洽、四系统共生环口径一致），不并行铺开。
3. **数值纪律**：公式引用数据表键名；数值禁硬编码进代码描述；给占位带与护栏。
4. **存档纪律**：设计中涉及存档字段时给出字段清单与破坏性变更提示（需迁移链），不实现。
5. **不写游戏代码**：本任务是规格产出；除非用户明确要求实现。
6. **语言**：全中文输出；术语/键名/代码片段保留原文。
7. **汇报节奏**：每模块产出后向用户汇报三行式（完成项 / 待拍板 / 开放问题），不静默推进；全部完成后再做总对账。
