# 科技树蓝图（Blueprint: Tech Tree）

> 状态：[讨论稿] ｜ 阶段：P0 已具形态，P1/P2 目标形态如下 ｜ 读取序：README → 本文件

## 一、定位

**玩家视角**：迷雾里的树不是"加点"而是"开门"——每点亮一个节点，多出一种选择（新任务、新基座、新档位、新赛道），而不仅仅是分数更高；**没有排他——所有节点都可以研究和升级**，我按自己的节奏点亮全部潜力，选择权在"先点亮哪条路"而非"放弃哪条路"。

**设计原则**：树=解锁新决策面（GDS 引擎+平台双轴的精髓），不是纯数值乘子；**与论文/模型/芯片你中有我、我中有你**——树解锁的研究方向就是论文选题，树解锁的基座/档位就是模型与芯片的入口，反过来论文产出、模型成果、芯片档位又回喂树的点亮；迷雾钩子=探索感（"??? 后面是什么"）；**任何节点效果改动必须与出分公式/饱和线/对手守卫带做数值联标推演**（树的分数贡献是出分公式的输入，动它=动全局分数曲线）。

## 二、目标形态（终态）

1. **节点效果分层（去 uniform）**：
   - **解锁型（主力）**：点亮节点 → 解锁新任务类型（论文选题）/ 新基座（模型）/ 新芯片档位（算力）/ 新赛道支线；
   - **数值型（少量）**：仅保留少数关键节点作为出分乘子；
   - **降费/效率型**：点亮 → 目录任务/训练成本下降（成本杠杆）。
2. **迷雾五态**：hidden / rumored / visible / researchable / lit；翻雾三通路（周推进揭示 / 竞对论文外溢 / 交叉进度）；"???"行+域计数=探索感主载体。
3. **全可研、无排他**：所有节点都可研究和升级（没有互斥路线）；选择权=点亮顺序与资源分配（先点哪条路），不是二选一放弃——后期满树=全能力集齐（"我已登顶"的完成感）。每域至少 1 个可达节点（防死路）。
4. **域特化加成**：各域效果差异化（深思=出分乘子、蒲公英=降复现费、长忆=解锁长上下文基座、器用=解锁工具任务线、通感=解锁多模态基座…），而非全局统一加成——域有性格，路有方向。**部分节点效果直接作用于产物 n 维评分**（如"推理增强"节点→模型"推理"维权重提升、"复现高效"节点→论文"复现性"维加分）——树是玩家定向强化 n 维的长期工具（与员工属性、芯片档位并列为 n 维三大来源）。
5. **饱和度护栏**：树对出分的总贡献有预算上限，与"首达满分周次 ≥ 阈值 / 对手守卫带"联动断言（树动→公式动→护栏重标，全部走数值收口）。
6. **与论文/模型/芯片的共生环**（你中有我、我中有你）：
   - 树 → 论文：点亮节点解锁对应域论文选题（研究方向的"菜单"由树打开）；
   - 树 → 模型：点亮节点解锁新基座（能训的模型随树走）；
   - 树 → 芯片：点亮节点解锁新档位/新赛道（算力门随树开）；
   - 论文 → 树：论文产出 RP（点亮燃料）由选题方向决定；
   - 模型 → 树：模型成果带来影响力/收入（点亮资源）；
   - 芯片 → 树：算力支撑大规模训练（更快攒出分与影响力）。
   - 共生环不意味着"一条链锁死"——任何一侧的进步都能带动其他侧，玩家可以从任意入口切入。

## 三、GDS 可复用语言

- **引擎=工具升级**：GDS 引擎研发让你能承接更高难度项目；本作"解锁型节点"承接此位；
- **平台=新市场窗口**：GDS 新机种带来新玩家群；本作"新基座/新档位/新赛道"承接此位；
- **组合表公开**：GDS 类型×题材组合表可查；本作任务×基座×域对照表公开（读表胜天）。

## 四、阶段路径

### P0 骨架：迷雾五态 + 翻雾三通路
- 内容：14 节点树（5 域+他者传闻占位），hidden→lit 五态，翻雾=周推进/竞对外溢/交叉；解锁谓词=阈值/外溢/交叉/灵感；域计数显示（n 域内已探明）。
- 判定 [P]：探索感成立（"???"让我想点亮它）；节点点亮有"开了新门"的反馈；保底机制防长期无翻雾。

### P1 深化：节点效果分层 + 共生环成形
- 内容：节点 effect 从"全局乘子"重构为分层效果（解锁/数值/降费三型）；域特化加成各就位；**与论文/模型/芯片的共生环闭环**（树解锁选题/基座/档位，论文/模型/芯片回喂点亮资源）；**同批完成出分公式/饱和护栏/守卫带联标推演**（tb 总量、首达满分周、L4 守卫带三线一致）。
- 判定 [P]：玩家会因"这条路给什么"而非"这节点加几分"决策；点树顺序有分歧（非唯一最优解，但无被放弃的路线）；树带来的分数成长曲线与对手守卫张力匹配（不被树过早推上封顶）；任意一侧（论文/模型/芯片）的进步都能感受到树在跟着活。

### P2 长线：扩树 + 全能力集齐
- 内容：节点数扩增（可研节点 >14 后重设占比口径）；他者道路（非 transformer 路线）作为后期大目标（传闻→真身，点齐=全能力）；域间交叉节点（如"端侧小模型"承接多域）；满树完成感（全 lit=已登顶）。
- 判定 [P]：后期"把树点满"是明确可追求的目标；点满后有"全能力集齐"的完成感（不靠排他制造重玩价值）。

## 五、系统联动

- 论文（选题带域标签→域 RP 权重→点树快的域；树解锁的域=论文选题池）→ **共生环：树↔论文**
- 芯片（树节点解锁新档位/新赛道；高挡位算力支撑树的大规模实验）→ **共生环：树↔芯片**
- 模型（树解锁新基座→更强模型；模型成果回喂影响力/收入）→ **共生环：树↔模型**
- 经济（降费节点→成本杠杆；点树消耗影响力）→ 供给面
- 竞对（翻雾外溢=竞对论文）→ 探索驱动
- 随机（灵感揭示时机）→ 探索钩子
- UI/UX（迷雾 C 方案/域计数/"???"行）→ 呈现层

## 六、开放问题（含评审指出的必答项）

1. **共生环数值闭环**：论文方向（域 RP 权重）→ 科技树（点亮路径）→ 芯片（档位解锁）→ 模型（出分/收入）四者必须在数值层打通，不能只有方向口号——补一卷推演页（供给 RP 如何被四系统分配、各侧进步如何回喂）；
2. 去 uniform 后 tb 总量预算：树的分数贡献削减后，出分公式的 A 曲线、首达满分周、对手守卫带（L1–L4 分数）必须同批重标——补推演页；
3. 无排他下"点树顺序"如何产生分歧（防唯一最优解）：依赖资源稀缺/时间窗口/成本曲线制造先后取舍，数值推演验证非唯一最优；
4. 非分数收益（Q7 类）与分数乘子的比例多少最能激励"交替点树"（防"永远最后点树"）；
5. **节点 n 维定向强化与 SOTA 守卫带的张力**：若节点直接推高模型某维度（如推理维）→ 单值 score 随之变高 → 会不会重演"点满树过早封顶"？n 维强化须与 tb 总量预算、首达满分周、守卫带联标（并入开放问题 2 的推演页）；
6. 树、员工、芯片三 n 维来源的权重分配（谁主导哪些维度），防"员工属性被树/芯片碾压成摆设"。
