# 员工规格（Staff Spec · 四件套）

> 蓝图依据：`blueprint-staff.md` ｜ 状态：[设计定稿·待拍板]
> 读取序：README → 蓝图 → 本规格 → `texts-keys.md` / `numerics-master.md`
> 全局骨架：统一任务槽 4 个（固定）；**员工上桌=派进任务槽项目**（论文/模型/算力三类共用槽位）；资源三件 cash/influence/card_hours_week；员工属性=产物 n 维评分的源属性之一（n 维三大来源：员工属性 × 科技树定向强化 × 芯片档位画像）。

## 0. 本模块定位

玩家视角：**人是我的棋盘**——招谁、练谁、谁和谁搭、谁上桌，每个决定都有可见后果；每位研究员有名字、有性格、有成长，是收集品也是棋子。

硬约束承接（制作人已拍板）：
- 初始 **4 人** → 扩编 **8 → 12 人**；扩编=一次性扩建费+新面孔；
- 任务槽 **固定 4 个**（不随人数增长）：人多≠多线程，多出来的人用于**项目协作/轮换**——决策深度压进"派谁上桌、谁和谁搭"，而非"开更多线"；
- 协作系数公开显示但必须防"唯一最优解"（≥2 个真实 trade-off，见 §D.3 对账）；
- 员工观察文本=**静态种子非轮转**（生成时确定性绑定，禁文案轮转）。

## A. 交互细节规格

### A.1 玩家操作清单

**OP-STA-01 快速指派（≤2 击）**
- 入口：员工区任一 idle 员工卡（主台常显实体卡）
- 操作：action_primary 点卡 → 可派项目列表（z1 微弹层，仅列**当前可接收**的槽位项目 + 预判行"匹配度 ★★★"）→ action_primary 点项目 → 完成
- 即时反馈：0.5s 内员工卡状态翻新"在岗：<项目名>"；项目卡追加头像角标；若为双人上桌 → 项目卡显示"组合效率 ×1.15"角标（0.5s 浮现）
- 结果：员工进入项目；读表面板（任务×员工×基座）该行高亮
- 异常/边界：无 idle 员工/无接收位 → 指派入口置灰+原因（`staff_assign_disabled_reason`）；**同一项目不可派同一人**（重复选择自动过滤+原因）；项目已满员（上桌上限）→ 该行标"满员"不可点

**OP-STA-02 员工详情翻阅（读表胜天）**
- 入口：员工卡 → action_secondary/长按 → z1 详情面板（`PanelId.STAFF_DETAIL`）
- 操作：翻页查看：档案页（名/岗位/稀有度/特质/观察句/在职年限）/ 属性页（4 维基础属性+成长曲线）/ 协同页（与各在岗者的组合效率表）
- 即时反馈：面板推入；属性数值变化有"数值在涨"动画（升级闪烁）
- 结果：全部信息只读可查；无隐藏数值
- 异常/边界：员工离岗/跳槽后详情页保留为"离职档案"（灰化+离职原因）；空态=无员工不渲染（P2 招募期占位卡 `staff_slot_empty`）

**OP-STA-03 培训课程（付费成长）**
- 入口：员工详情 → "培训"标签（z1 内）→ 课程列表（每课程：目标属性+费用+当前收益倍率）
- 操作：action_primary 选课 → 确认扣费 → 周结结算成长
- 即时反馈：确认后课程卡标"培训中·第 X 周"；完成周结时属性跳动 +"数值在涨"动画
- 结果：属性提升；该课程收益倍率递减（抗药性，见 D.2）；周报一行"<名字>完成 <课程>"
- 异常/边界：资金不足 → 选课键置灰+原因（`staff_train_disabled_reason`）；员工已跳槽/解雇 → 培训自动取消（学费按比例退款 50%）

**OP-STA-04 转岗**
- 入口：员工详情 → "转岗"（P1 起）
- 操作：action_primary 选新岗位 → 确认（显示适配矩阵变化预览"数据岗 2.2→工程岗 1.6"）
- 即时反馈：岗位标签翻新；属性权重预览即时刷新
- 结果：岗位变更（下个周结生效）；转岗冷却 8 周（防反复横跳）
- 异常/边界：冷却期内转岗键置灰+原因（`staff_transfer_cd_reason`）；P0 未开放转岗时入口不出现（空态=不出现）

**OP-STA-05 挖人 counter-offer（决策卡，P1 起）**
- 入口：竞对挖人事件 → z2 决策卡（世界等待）
- 操作：二选一：加薪留人（成本=年薪 +20%，立即扣）/ 放人（员工离职，周报记"<名字> 加入了深巷科技"）
- 即时反馈：选择后卡收起 + 0.5s 内员工卡状态翻新
- 结果：留人=成本支出+忠诚上升（后续挖人概率降低）；放人=影响力 -10（人才流失新闻）
- 异常/边界：资金不足留人 → 留人键置灰+原因（`staff_retain_disabled_reason`）；同一员工被挖 ≤2 次/局（防骚扰腻点，见 rivals-spec）

**OP-STA-06 解雇（有代价）**
- 入口：员工详情 → "解雇"→ 二次确认弹层（显示代价预览"影响力 -15"）
- 操作：action_primary 确认 → 员工离岗
- 即时反馈：员工卡移除动画（0.6s 淡出）；周报记一行
- 结果：空出人手；影响力代价入账；被解雇员工不再入池（收集图鉴保留"离职"态）
- 异常/边界：在职未满 4 人时解雇键置灰+原因（`staff_fire_floor_reason`："实验室至少留 4 人"）；误触可取消（二次确认必弹）

**OP-STA-07 招募市场（P2，z1 面板）**
- 入口：Dock/图鉴 → "招募"（8 人后开放）
- 操作：候选池刷新（消耗猎头门票，门票=周结自然 +1，上限 3）→ 看简历（贵=可见信息多：R 级只看名+一句话；SR 级看岗位+适配；SSR 级看全属性）→ 签约
- 即时反馈：签约成功 → 候选卡移出 + 主台员工区联动刷新（+1 卡）
- 结果：新员工入职（下个周结到场）；签约金一次扣
- 异常/边界：现金<签约金 → 签约键置灰+原因（`recruit_sign_disabled_reason`）；门票=0 → 刷新键置灰+原因（`recruit_refresh_disabled_reason`）；员工满编 → 招募入口置灰（`recruit_full_reason`："先扩编到 12 人"）

### A.2 输入抽象

与 onboarding 共用：`action_primary`（确认/指派/签约）、`action_secondary`（返回/取消/长按详情）、`action_pause`、方向键（详情面板页签焦点）。触屏目标 ≥48px；员工卡在竖屏折叠为横滑行（卡高 ≥48px）。

### A.3 四态定义（员工模块）

| 态 | 定义 | 视觉/文案 |
|---|---|---|
| 空态 | 未招满时的空缺位 | 占位卡 `staff_slot_empty`（"空位·待招募"），非空白；4 人初始无空位 |
| 禁用态 | 指派/培训/签约/解雇不可执行 | 入口置灰+原因句（键名见 A.1）；禁用不等于隐藏 |
| 加载态 | 候选池刷新/详情页数据就绪 | 骨架屏 ≤0.5s；刷新失败走错误态 |
| 错误态 | 状态机自检失败（员工引用悬空等） | 详情页显示"档案损坏"占位+error 上报，不崩主台 |

### A.4 触屏与竖屏/横屏差异表

| 场景 | 竖屏 | 横屏 |
|---|---|---|
| 员工区 | 横滑行（单行卡：名+状态+在岗项目），≥48px 卡高 | 网格 2–3 列实体卡 |
| 详情面板 | 纵排满宽，页签顶部横滑 | 居中弹层，页签左侧栏 |
| 协作组合角标 | 项目卡内小角标（×1.15） | 项目卡旁并排双人头像+角标 |
| 招募市场 | 候选卡单列满宽 | 双列 |
| 培训选课 | 课程单列 | 课程双列 |

### A.5 [P] 试玩验收句

- [P] 主台 4 名员工实体可见，指派 ≤2 击完成；"我安排的人确实在干我安排的活"（前置：任意员工 idle → 操作：点卡→点项目 → 预期：0.5s 内卡翻新+项目卡头像角标；代理指标：≤2 击）。
- [P] 8 人团队有"实验室变大了"体感，但任务槽仍 4 个不变忙乱（前置：扩编 8 人后 → 操作：扫一眼主台 → 预期：人多但槽位列表无新增，决策在"派谁"）。
- [P] "两人一起做，快 1 天"有体感且可见（前置：模型训练项目双人上桌 → 操作：对比单/双人剩余周数 → 预期：项目卡显示组合效率角标且剩余周数可见缩短）。
- [P] 员工状态带可预判："他这周摸鱼，出活会慢一点"（前置：状态带"摸鱼"周 → 操作：读员工卡 → 预期：状态标签+产出区间提示同屏）。

## B. UI·UX 规格

### B.1 呈现载体与层级

- 员工区：z0 主台四主区之一（实体卡常显）；协作组合角标=z0 项目卡内嵌
- 详情面板：z1（`PanelId.STAFF_DETAIL`）；培训/转岗在详情内嵌页签（不新增注册项）
- 挖人决策卡：z2（决策卡先于周报）；招募市场：z1（`PanelId.RECRUIT_MARKET`）
- 收集图鉴：z1（`PanelId.COLLECTION`，P2；员工相册页签）
- 新增注册项：STAFF_DETAIL / RECRUIT_MARKET / COLLECTION（注册表 +3，过命令落点核对）；Dock 三键冻结不变

### B.2 状态-视觉映射表（本模块行）

### B.3 重点感知排序落实

员工属性变化=第二视觉（属性与产物 n 维评分变化同列）：升级闪烁、"数值在涨"动画、状态色带、协作角标全部 L1 轻量；员工区视觉权重 < 工作区（任务进度第一），> 资源栏。

### B.4 动画预算（本模块消费）

全部 L1 轻量（卡片翻新 0.5s/属性跳动 0.5s/色带过渡 0.4s）；解雇淡出 0.6s；本模块不消费 L2/L3。

### B.5 竖屏折叠 / 可达性

- 员工区竖屏折为横滑行；工作区永不折叠；
- 状态色带=色+文字双通道（色盲友好：专注=蓝+"专注"字样）；
- 属性数字变化双通道：数值上跳+背景闪烁（不单靠颜色）；
- 对比度/字号同 onboarding 口径（正文 ≥14sp，可点元素 ≥48px）。

### C.3 考据纪律落实

- 岗位四类全部对应 2022 年真实实验室工种（研究/评测/数据/工程），**无"灵光一闪"式泛化**；
- "数据岗适配 ≥ 算法"落实为：数据岗对"数据"属性的收益系数为最高档（见 numerics-master 岗位矩阵）；
- 状态带=机制随机（周粒度掷骰），观察句=静态种子，**禁文案轮转/禁把随机写成装饰**（README 评审吸收 4/否决项 1）；
- 培训抗药性=数值递减（非文案暗示），转岗冷却=数值约束。

### C.4 员工观察句（静态种子示例，池入 texts-keys 总表）

> 每个员工生成时从池中**确定性取 1 句绑定，永不再变**（不轮转）。示例：
- staff_observation_pool_01 「复现别人的论文，先怀疑别人的代码。」（研究岗）
- staff_observation_pool_02 「eval 跑不过就是跑不过，不找借口。」（评测岗）
- staff_observation_pool_03 「脏数据喂出来的模型，跟人吃地沟油一样。」（数据岗）
- staff_observation_pool_04 「卡不够就优化，优化不动就排队。」（工程岗）
- staff_observation_pool_05 「我的周末属于梯度下降。」（通用）
- staff_observation_pool_06 「论文被拒那天，我在调参。」（通用）

### C.5 敏感词三层

命名/实验室名/员工自定义名共用三层（键名见 onboarding C.5）：`name_filter_whitelist` / `name_filter_blocklist` / `name_filter_homophone_map`；错误提示统一 `name_filter_reason`。

## D. 数值规格

### D.1 数据表键名规划

- `staff.json`：初始员工表（4 人）、岗位定义、属性成长、培训课程、观察句绑定、招募池参数

### D.3 蓝图内部一致性对账（本模块）

- ✅ 规模 4→8→12 与扩编费节奏（蓝图 §二1 + README 评审吸收 9）；
- ✅ 任务槽固定 4 个不随人数增长（蓝图 §二2）；决策深度=上桌人选与协作组合（蓝图 P1 判定"同一任务我会犹豫派谁"）；
- ✅ 协作系数公开显示（员工卡/项目卡角标）——**防唯一最优解的对账**（蓝图开放问题 2）：组合效率 × 岗位适配 × 状态带 × 课程投资构成 ≥2 个正交 trade-off（同岗虽慢但免费/互补虽快但需凑人+转岗冷却），组合表全公开但无"恒最优对"；具体期望收益推演见 numerics-master §员工·防伪决策推演；
- ✅ 状态带=周粒度、产出带可读、pity 保底（README 评审吸收 4 + 随机蓝图 §二2）；
- ✅ 观察句=静态种子非轮转（README 评审吸收 3 否决项 1）；
- ✅ 员工属性=产物 n 维源属性（蓝图 §一"人的属性变化与产物 n 维评分变化同一套可见语言"）；映射表落 papers/models/chips 规格 + numerics-master §n 维合成；
- ✅ 数据岗适配 ≥ 算法岗（蓝图 §二3）：岗位矩阵中数据岗对"数据"属性收益系数为最高档（考据锚=2022 数据工程）。
