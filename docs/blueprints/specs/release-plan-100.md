## 四、issue 拆分规则（落 GitHub 用）

1. 每批每功能点=1 issue（规模 S/M/L 标注）；**issue 模板按 issue-spec.md 三段式**（[T] 注 GUT 用例名/[P] 试玩语言）；
2. issue 正文附：目标/依赖/规模/决策依据（DR 或 decisions-100 编号）/验收点/实施提示（architecture-100 章节+数据表键名真源）；
3. 标签：`status/scheduled` + 批号（`batch:0`…`batch:6`）+ 规模标（`scale:s/m/l`）+ 关键路径 `p0-critical-path`；
4. **数据表先行的拓扑**（架构 A4）：批0.6 先立 schema 断言框架 → 各批功能点 issue 引用对应数据表建表为前置；
5. 关键路径 issue 合 main 必须 verify 全绿 + 验收点自证表。
