# 芯片系统蓝图（Blueprint: Compute / Chips）

> 状态：[讨论稿] ｜ 阶段：P0 已具形态，P1/P2 目标形态如下 ｜ 读取序：README → 本文件

## 一、定位

**玩家视角**：算力是我的"设备等级"——买卡不是填数字，而是开新门（能训更大的模型、能上更多人、能走新路线）；算力是稀缺资源，每次开训都要掂量"这周够不够烧"。

**设计原则**：卡时=每周预算（周结重置，防"卡池扣减"把训练卡死）；档位=供给量+解锁面的双重语义（买卡=打开能力门）；训练永远供得上（但供得很紧）；**芯片与科技树/论文/模型你中有我、我中有你**——树解锁的档位才能买、论文实验消耗算力、芯片档位决定能训多大模型，模型成果又赚回买卡的钱（共生环的一环）；**档位绑定解锁面属结构改动，须先过复议**（防越权扩槽）。

## 二、目标形态（终态）

1. **n 维质量画像（芯片的核心感知之一）**：每一档芯片有 **n 维质量评分**（如算力/能效/成本/稳定性，维度集随自研线扩展）；n 维加权合成单值"芯片品质分"；n 维可读可决策——"这档算力猛但费电""这档便宜但爱抽风"= 选型与升级的决策依据；**n 维变化与任务进度同为主台重点感知**（配合 UI/UX 蓝图重点感知排序）。
2. **档位双语义**：每一档=卡时供给量（8/16/32/64 量级）+ 启动训练的门槛（基座要求的最低档）；档位随经营阶段递进。
2. **解锁面（P1 评审）**：升档 → 解锁更高基座训练 + 打开能力门；**档位解锁与科技树节点联动**（树点亮某节点 → 对应档位开放，例：点亮工具域节点 → 高档位训练开放；升档反过来支撑树的大规模实验）——解锁不与"扩任务槽"绑定（扩槽是独立红级项）——**能力门=挂算力叙事的新系统入口，不做槽位改动**。
3. **周预算纪律**：每周卡时=供给或剩余（周结重置）；超过分配拒绝（并给出"还差多少/何时够"提示，而非静默卡死）；训练时长=定值（不随随机波动）。
4. **支线（P2 立项）**：自研芯片/租用超算二选一（长期效率 vs 一次性投入）；算力出租/共享（危机态支线收入）；集群训练（多基座并行，后期形态）。
5. **价格与升级**：档位价格递增，购买=一次性大开支（里程碑感）；升级时机=规划决策；各档 n 维画像公开可查（读表胜天：能效/成本 trade-off 摆上台面）。

## 三、GDS 可复用语言

- **平台换代=新市场窗口**：GDS 新机种=新玩家群/新游戏类型；本作档位=新训练形态/新赛道（**能力门语义承接，不做年代际换代结构**——平台换代长线已裁不进，禁照搬外壳）；
- **设备购买=里程碑**：GDS 买新机是长期投资；本作升档=一次性大开支换长期能力。

## 四、阶段路径

### P0 骨架：周预算 + 档位门槛
- 内容：卡时=每周供给+周结重置；基座要求最低档（越小模型要求越低，越大的模型/人越多要求越高）；训练启动前校验"本周预算够不够"；档位购买入口（一次性开支）；**档位 n 维画像起步展示（算力/能效/成本/稳定性，维度权重公开）**。
- 判定 [P]：玩家能说出"我现在一周能烧多少卡时、够训什么"；开训被拒绝时有明确原因（差几卡时/何时够）；买卡前能看到"这档强在哪、贵在哪"。

### P1 深化：档位解锁面 + 超分配提示 + n 维决策
- 内容（**结构改动须复议**）：升档解锁能力门（新训练形态/新赛道，与科技树解锁联动）；超分配拒绝给"还差 X/约 Y 周够"的可读提示；卡时余量/使用率可见（资源栏+tooltip）；**n 维画像可视化（雷达/条形）**——能效↔成本↔稳定性的 trade-off 摆上台面，玩家为"上不上这一档"权衡。
- 判定 [P]：升档有"开了新门"的反馈（能训新模型/上新路线）；玩家会为"上不上这一档"犹豫（真实经济与战略权衡）；n 维画像让"贵得值不值"有依据。

### P2 长线：支线选型 + 集群
- 内容（**逐项独立立项**）：自研芯片 vs 租用超算（选型决策，**自研=定制 n 维画像**：自研可定向强化某维度）；算力出租/共享（危机收入支线）；集群训练（多基座并行，配合模型迭代线）；算力供给曲线随阶段重标（与 V-sim 套跑）。
- 判定 [P]：后期算力是"经营战略"而非"数值充能"；单局内算力来源随阶段演化（租借→自购→自研）；自研芯片有"我定制的算力"的成就感。（不做多周目继承。）

## 五、系统联动

- 模型（档位门槛→能训的基座）→ 能力门（共生环：算力撑训练）
- 科技树（树节点解锁档位/赛道；算力支撑树的大规模实验）→ 共生环
- 论文（论文实验消耗算力；论文影响力→算力资助）→ 共生环
- 经济（买卡开支/算力出租收入）→ 收支面
- 时间（周预算重置节奏）→ 周账本
- 员工（多人上桌随基座→卡时消耗）→ 人手×算力双稀缺
- UI/UX（资源栏卡时/余量 tooltip）→ 呈现层

## 六、开放问题

1. 档位解锁面与"多任务槽"的关系：**解锁面不做槽位改动**（扩槽=独立红级），但"算力支撑并行"叙事如何表达不越权；
2. 自研芯片 vs 租用超算的决策维度（长期效率 vs 现金流 vs 叙事绑定哪条线）；
3. **芯片 n 维画像的维度集与权重**：算力/能效/成本/稳定性 4 维起步？每维对训练效率/出分的换算（能效→卡时价值、稳定性→中断风险）——数值推演先行；
4. 芯片 n 维与档位价格/解锁面的关系（n 维是否随档位单调提升，还是刻意制造档位间 trade-off——低档能效高/高档算力猛但费电）。
