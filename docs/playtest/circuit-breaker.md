# 停线复盘一页纸（circuit-breaker）

> 性质：试玩反馈熔断协议（DR-030）。与 gd-issue-pipeline §5 blocked-human（实现熔断）区分：本页管**体验熔断**。
> 依据：v0.1.2/v0.1.3 两批试玩反馈暴露缺陷的复发教训。

## 1. 触发条件（任一即触发）

- 同类反馈（"看不见/没反应/不知道状态"类缺陷）**≥2 条**；
- 核心循环阻断（无法推进/无法理解下一步）**1 条**；
- "同类"判定权：**制作人席**（分诊时归类，防"不同类"话术绕开）。

## 2. 影子模式（先行期）

- 影子期**只记录不拦截**：每次触发条件满足时在 issue 评论 `[breaker-shadow] 类别/时间/触发条目`，不停线；
- 跑满 1 批真实试玩后，用影子数据校准阈值，再启用真停线（制作人宣布切换）。

## 3. 停线动作（真熔断生效后）

1. 暂停新建实施 issue（存量在跑批次完成或冻结，制作人定）；
2. 四席 24h 内复盘：根因归类（排期/规格/实施/验证哪几个卡口连环放行）+ 产出修复 issue（走新规格）；
3. 修复 issue 合入后恢复运行；复盘纪要归档 docs/playtest/。

## 4. 反馈入口规范（影子模式的数据前提）

- 试玩反馈一律 issue 化（固定表单：环境/复现步骤/原话逐字/截图）；
- 分诊席保留原话，禁意译加工；修完必答"用户原话被哪条新增验收点捕获"。

## 5. 轻度复议正门

停线复盘会上允许对"仅稿面裁决"（无试玩验证）的 DR 提轻度复议：有门槛（须试玩证据）、一次一议、黄级流程；非重开裁决。
