# 0012. RP 供给真源：任务 `rp_output` 唯一来源 + 翻雾供给源改为累计影响力

日期：2026-09-08 / 状态：accepted / 落 DR-031（§2.9 第 1–4 条、A1 第 2 条、A2）与 issue #76（批 1e）

## 背景

V6 的供给锚 `assertion_bounds.json.v6_tech_lit_distribution.supply_anchor_rp = 12300`
来自 `balance-preview` 的"Σ研究力 195 × 研究时间占比 30/40/50%"**连续模型**。
全仓代码实证（`game_world.gd` 任务结算 / `event_engine.gd` 效果）：

- RP（= 影响力同一池）**唯一来源 = 任务 `rp_output` + 事件 `rp_grant`**；
- **不存在"研究力每周产 RP"的任何通路** → 该锚在实现中悬空，A1/A2 的数字前提不成立。

同时 `game_world.gd` 把**影响力当前余额**传给 `tech_fog.advance(cumulative_rp)`：
玩家点树消耗影响力会**隐式拖慢翻雾进度**（D-12 实参错位）。

结构性问题（纪要 §2.8）：单任务槽下"课题无 RP / 研究无收入"使 gate 与科技树**互斥**——
纯课题 24 周收入 25.2 万但 RP 恒 0（`tech_bonus` 锁死），纯研究有 RP 但收入 0。

## 决策

**① 承认任务 `rp_output` 为 RP 唯一来源**；`balance-preview` 连续模型降级为近似参考，
不再作为供给锚。

**② 供给标定改为"单位时间供给"口径**：`tasks.json` 的 `rp_output / duration_weeks`
落在 `[31, 42] RP/周`（当前实表 35–37.5）→ 160 周单槽串行 ≈ **6000 RP**，
落目标带 `[4910, 6810)` ⇒ 现状 `Σrp_cost = 14210` 下 **V6 点亮 7 个**（P50=7）。
**Σrp_cost 禁调**（A2 撤销调表）；调表降级为条件项（仅当实测供给 >6.8k 时才复议）。

**③ 供给锚改判**：`assertion_bounds.json` 的 `supply_anchor_rp: 12300` 替换为
`supply_band_rp_min: 4910` / `supply_band_rp_max: 6810`（半开区间 `[4910, 6810)`）。

**④ 翻雾供给源 = 累计获得影响力 `cum_influence`**（只增不减）：
- `Economy` 维护 `_cum_influence`，只吃 `apply_delta("influence", +amount)` 的正向过账；
  点树消耗是负向过账，**不减少**累计值 → "点树不拖慢翻雾"（RK-04）；
- `TechFog.advance_with_context({cum_influence: …})` 为唯一供给入口；
  **旧签名 `advance(cumulative_rp)` 保留**并转调（测试改动面最小，语义 = 直接传入累计值）；
- 入档 `flags.cum_influence`（开放容器加键 → **零迁移**，旧档缺键兜底 0）。

**⑤ 课题类任务补 `rp_output`**（破除 §2.8 的钱/RP 互斥）：课题 0 → 150，
纸面复现 50 → 110，灵犀复现 100 → 140；基础研究维持 150。

## 理由

1. **口径可复现**：供给 = 任务笔数 × 单笔 RP，"研究时间占比"不改变总供给（§2.9 关键认识）；
   按单位时间标定后，**任意任务选择策略**的 160 周供给都落带（数据表级断言兜底）。
2. **破除结构性互斥**：课题同时产钱与 RP 后，"钱 vs RP"从互斥变为**配比**决策。
3. **翻雾语义单点**：累计计数器只增不减，玩家点树不再与探索进度耦合；`cum_influence`
   同时为后续"影响力曲线"类断言提供唯一口径。
4. **零迁移**：`flags{}` 与 `rng{}` 同为开放容器，加键即生效；`staff.assigned` 等形状不变。

## 备选方案

- **维持 12.3k 锚并上调 `Σrp_cost`（否决）**：该锚无产出通路；上调后供给仍 ~6k，
  点亮数反而降到 5–6，V6 下限破线。
- **按"研究时间占比"连续产出 RP（否决）**：需要新增每周 RP 产出通路（新 RNG/新结算步骤），
  且与"任务结算才是唯一收入口径"（ADR-0015 / DR-031 C1）冲突。
- **翻雾继续读余额（否决）**：点树消耗会拖慢翻雾，玩家决策被隐性惩罚（D-12）。
- **`cum_influence` 入 `resources{}`（否决）**：`resources` 是"当前持有量"语义，
  累计值属派生统计 → 入 `flags{}` 开放容器。

## 后果

**正向**：V6 断言自洽（`supply_band` 与实表复算一致）；科技树与 gate 不再互斥；
翻雾进度与点树解耦；供给口径单一（任务表即真源）。

**代价 / 风险**：
- `tasks.json` 的 `rp_output` 变化会改变 V6 实跑分布与万周哈希（行为修正）；
- 事件 `rp_grant` 仍计入供给（#75 已把单卡压到 ≤60、期望 ~4.2/周 ≈ 供给的 8%），
  属"联标内"的次要来源；
- 供给带为**半开区间**，上界 6810 不可取等（等于 C(8) 时点亮数跳变到 8）。
