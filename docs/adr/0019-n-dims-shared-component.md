# 0019. n 维评分=共享组件 n_dims（单合成公式真源）

日期：2026-09-10 / 状态：accepted

## 背景

论文/模型/芯片三产物各有 n 维质量画像（论文 4 维：创新/严谨/影响/复现；
模型 5 维：推理/知识/对话/速度/成本；芯片 4 维：算力/能效/成本/稳定性）。
numerics-master §1.1 裁决：三产物合成公式同构 = Σ(维×权)，分数 ∈[0,100]。
若按产物各自实现，三份代码=三份漂移风险；n 维扩展（P2 加维/加产物）
= 每份代码同步改，违反单一真源。

## 决策

**n_dims.gd = 三产物共享的合成引擎（单一公式真源）**：

- `compose(profile, sources)`：逐维 Σ(源×源权重)，返回 DimResult{values: Array, score}；
- **维度永远数组化**：values/weights/dim_ids 全部 Array，配套每产物一个
  dim_label_key[] 文案键数组；新增一维 = 表 + 文案键数组加一项，代码零改动；
- ndim_profiles.gd = 表驱动适配层（各表 dims/weights 数组 → DimProfile 结构体，
  唯一转换点，不 import 数据）；
- 三源合成：员工贡献 × 科技树定向强化 × 芯片档位画像——各系统只交"自己那份
  原始值"，合成单一化（芯片发挥波动/状态带波动在合成点登记入 rng 域统计）；
- 饱和护栏：saturate_clamp / guard_check（98 饱和带/首满 W80/守卫带）同文件。

## 备选方案

- **按产物各写合成**：三份 Σ(维×权) 代码漂移，与 numerics-master"单公式真源"
  裁决冲突，放弃。
- **公式写进数据表表达式**：运行时解释表达式，过度设计（公式只有一种形态），
  且表表达式不可单测，放弃。

## 后果

- 正向：公式一处实现四处复用；维度扩展=数据增长；GUT 对账①
  `test_ndim_formula_all_products` 单点断言三产物。
- 代价：产物类必须先声明维度布局/来源权重再调 compose（少一层自由度）；
  数组化字段入档需与存档 schema 配合（numerics-master §八）。
