# 0026. 表现层契约升级：数据面=只读深拷贝 + 命令面=显式注册 + 快照唯一映射点

日期：2026-09-10 / 状态：accepted

## 背景

ADR-0016 已立 L2 数据面契约（数据面只读查询 / 表现层零业务计算），但 v0.1.x
末期暴露三类缺口：L3 曾直读 roster 内部对象（ADR-0016 对账表）、数据面方法
与命令面未显式分列（带副作用方法伪装 get_* 的风险）、存档/快照/呈现三方口径
各自为政。v1.0.0 系统数 4→11，缺口放大为架构风险。

## 决策

**三件套契约升级（architecture §5.1）：**

1. **数据面 = L2 门面只读方法**：一律 `get_*_view()` 返回深拷贝字典/数组/int/
   String，**不返回 L2 内部对象引用**（防 L3 越权改状态）；
2. **命令面 = 显式注册契约命令清单**（World 门面，可 grep）：每命令=一个玩家
   操作或系统装配落点；只读查询不进命令面（ADR-0016 决策④继承）；
   L3 禁止直调非契约方法；
3. **快照 = 唯一映射点 SnapshotCodec**：World↔存档/快照字典映射只此一处；
   存档/读档首渲染用 ui_snapshot() 全量只读快照；运行中增量走数据面查询 +
   信号驱动重渲染；不新增"预告类"信号（预告=查询，进数据面）。

## 备选方案

- **继续 ADR-0016 原状不加命令面清单**：契约方法散落 World，无法 grep 审计，
  死命令/越权调用风险随系统数放大，放弃。
- **L3 可拿内部对象引用**（旧 roster 直读形状）：越权改状态无防线，
  违反 H4，放弃。

## 后果

- 正向：契约可达可审计（test_contract_commands/test_view_contract）；
  三方口径同源（存档/快照/呈现）；L3 只画的结构性保障。
- 代价：数据面深拷贝有轻微性能成本（每帧视图查询）；命令面注册清单需随
  P0 操作清单逐条核过（架构 §5.1 注）。
