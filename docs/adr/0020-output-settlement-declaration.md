# 0020. L2 产出结算声明模式（项目完成不发资源，Settlement 按型路由唯一过账）

日期：2026-09-10 / 状态：accepted

## 背景

v0.1.x 曾有三类事故（ADR-0015 背景 1/4 + v0.1.3 #104）：项目完成时直接发钱/发分
导致账目不闭合（改了资源却无 ledger 行）；产出逻辑散到 L3 呈现时才决定（缺 view）；
同周多项目完成串行揭晓无契约。v1.0.0 架构 §4.3 要求统一"产出结算声明"模式。

## 决策

**项目完成不直接发资源。统一模式：**

- Project._on_finished() → 产出结算声明（纯数据产出对象）→ Settlement 收集；
- Settlement 按产物类型**单一 match 路由**：
  - paper → PaperArchive.archived + 域 RP 入账 + influence/cash 过账；
  - model → ModelLibrary.archived + 出分计算/命名待办 + SOTA 判定；
  - compute → ChipYard/能力解锁（P2 分支）；
- **所有资源变更一律经 Ledger 唯一过账口**（ADR-0015 账期契约继承）；
- 与 ADR-0015 周结步序合并为同一结算管线（architecture §5.3 phase 0–10）。

## 备选方案

- **项目直接改资源**（旧形状）：绕过 ledger 账目不闭合；周报收支对不上
  （ADR-0015 已实证），放弃。
- **L3 呈现时临时决定产出**：逻辑入表现层，缺 view/不可单测，违反
  H4 表现层零业务计算，放弃。

## 后果

- 正向：账目闭合（ledger 收支净=0 恒等可断言）；产出路由单一 match 可扩展
  （P2 加算力项目=加一个分支）；同周多完成串行揭晓有契约（按槽序）。
- 代价：Settlement 为 L2 核心编排类需严控 ≤500 行；产出对象为纯数据类
  （多一个小类）。
