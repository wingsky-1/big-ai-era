# 0009. TechFog 采用独立纯函数组件（不复用 L1 state_machine）

日期：2026-09-07 / 状态：accepted

## 背景

架构稿 v1.0 自评遗留②（v1.1 G 节保留）：迷雾五态
（hidden/rumored/visible/researchable/lit）的承载物——复用 L1 通用
`state_machine`，还是为 `tech_fog.gd` 建独立纯函数组件？v1.1 已按
"tech_fog.gd（五态+表级 fog_gate）"落清单，本 ADR 补正式裁定与理由。
倾向已定（独立），本文档闭环。

## 决策

**裁定：独立**。`tech_fog.gd` 为 L2 RefCounted 纯函数组件，表驱动转移表+
防软锁 pity 自成闭环；不复用 L1 `state_machine`。

## 理由

1. **语义不同构**：L1 `state_machine` 是面向实体行为的运行时 FSM
   （进入/退出生命周期、信号驱动）；TechFog 是**数据层状态投影**——每节点一个
   状态值，由周结管线第 7 步对全树一次批量求值，没有逐节点生命周期回调。
2. **领域闭环自成一体**：五态转移+表级 `fog_gate{rumored,visible}` 增则
   （parents 全 lit ⇒ 升 crossover）+防软锁 pity 保底，是一个自洽的规则集；
   复用通用 FSM 须在其上挂领域回调与查表逻辑，**污染通用状态机语义**
   （L1 服务从此依赖 L2 数据表 techs.json，反向违反分层）。
3. **可测性要求纯函数**：五态转移表全覆盖断言（TF2）、翻雾三通路触发断言、
   分位数断言（V6 点亮分布/V10 空窗）全部要求"字典进、字典出"的无头纯函数。
4. **存档对齐最简**：`fog_visibility / crossover_progress / pity` 直接映射
   状态字段，独立组件与 SnapshotCodec 一一对应。

## 备选方案

- **复用 L1 state_machine（否决）**：见理由 1/2——批量求值语义与生命周期
  语义错配，且迫使 L1 反向依赖 L4 数据表。
- **内嵌 TechTree 字段（否决）**：迷雾是"揭示节奏"系统，与"点亮"语义正交；
  pity/外溢/交叉进度内聚于独立单元，混入 TechTree 会让点亮与揭示互相缠绕，
  违反单一职责。

## 后果

- 正向：转移表可机械全覆盖单测；迷雾调参（fog_gate/pity 区间）纯数据；
  与 ADR-0008 确定性框架天然兼容（推进零 RNG）。
- 代价：L2 多一个组件（全 RefCounted，可接受）；"迷雾态"与"通用 FSM"两套
  状态词汇并存，新人需读本 ADR 理解为何不共用。
- 演进红线维持：他者道路若需互斥竞争态 → TechFog 扩态=红级（存档迁移），
  届时专项评审（DR-003 唯一已知红）。
