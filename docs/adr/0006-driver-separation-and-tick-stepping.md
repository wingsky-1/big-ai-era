# 0006. 驱动分离：View 停喂 tick 与模拟层 tick 步进

日期：2026-09-07 / 状态：accepted

## 背景

时间模型=实时流淌制（~10s=1 周，1x/2x/4x 变速，可暂停）。若把"真实时间流速"
引入模拟层，万周模拟、读档回放、同 seed 双跑等确定性验收全部失效；变速与
"关页/后台不可见"两种诉求若各自在模拟层加状态，会污染 L2 纯度
（DR-019 玩家之声②：关页面=暂停，零模拟层改动的实现路径待定型）。

## 决策

1. **模拟层永远 tick 步进**：`GameClock` 只认"刻"——View 每帧把 Δt 交 L0
   `clock_math` 累积，满刻步进一刻，满周触发 `settle_week()`。模拟层不知道
   "秒""帧""流速"的存在。
2. **变速=View 层系数**：1x/2x/4x 只是 GameLoopDriver 喂给 accumulator 的
   Δt 缩放，L2 零感知。
3. **停喂 tick（"只在场才流淌"）**：关页面/后台不可见=View 停止喂 tick；
   周报自动弹（z2）=临时停喂，pop 完成帧恢复。停喂是 View 行为，**不是**
   `GameClock.paused` 状态——不新增任何入档状态，零模拟层改动。
4. **暂停双源 OR 合成**：`paused = user_paused OR blocked_by_card`；
   `set_paused` 只写 `user_paused`，L2 忽略与 pending 冲突的解除请求
   （真值表 4 组合有单测）。

## 备选方案

- **可见性状态进 GameClock**：加 `page_visible` 字段并入 paused——多源语义混杂，
  且把 UI 生命周期泄进 L2，拒绝。
- **后台继续模拟**：移动耗电+回前台瞬间跳周，"缺席安全"卖点归零，拒绝。
- **时间缩放进模拟层**：破坏"刻"的步进纯度，万周模拟与真实游玩不再同通路，拒绝。

## 后果

- 正向：headless 万周模拟（<~5s）与真实游玩共享同一代码路径，verify.sh 的
  万周模拟/同 seed 双跑哈希因此成立；停喂与暂停解耦，"世界等玩家才停"白名单
  语义清晰；移动碎片场景（切微信回来 10 周照走）天然成立。
- 代价：iOS `visibilitychange` 可靠性须真机验证；移动端硬杀进程丢当前周
  （≤10s，写入已知限制）；周报停喂依赖 PanelStack 生命周期正确 pop。
