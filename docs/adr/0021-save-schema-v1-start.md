# 0021. 存档 v1.0.0 schema 起步与旧档弃迁

日期：2026-09-09 / 状态：accepted

## 背景

v1.0.0 重建采用全新架构（architecture-100）：11 系统职责重排、键名重建、
数值全部外置 `src/data/*.json`。旧 v0.1.x 存档的 schema 语义（旧键集、
旧资源口径、旧任务/树形状）与新版**完全不兼容**——若对旧档做迁移，
等于维护两套语义映射，成本高且极易坏档。同时 AGENTS.md 红线 6 要求
任何破坏性存档变更必须走 `SaveMigrator` 迁移链 + 单测，因此新 schema
从立项起就必须带版本号与迁移纪律。

## 决策

1. **schema_version = 1 起步**：v1.0.0 首版存档顶层强制携带
   `schema_version: 1`（顶层结构见 architecture-100 §9.1）；
   缺失版本号字段的存档一律按 v1 处理（不视为旧版）。
2. **旧 v0.1.x 档不迁移、只弃**：schema 语义全变，重建首版直接以
   v1 起步，旧实现作废（decisions-100 §〇），不提供 0→1 迁移步骤；
   加载时旧档因结构校验/壳补齐失败被拒，磁盘原档保留。
3. **未来版本才承担迁移义务**：从 v1 起，任何破坏性变更
   （键名重构/结构重组）一律走 `SaveMigrator` 迁移链逐级升轨
   （v1→v2→v3…，禁跳步）+ 对应单测；"当前版本起步、旧档不迁移"
   是 v1.0.0 的一次性弃迁，不是常态。

## 备选方案

- **旧档 0→v1 兼容迁移**：需保留 v0.1.x 全量旧形状映射，与"旧实现作废
  （禁读旧 src/）"红线冲突，且迁移结果语义不可信，否决。
- **不带版本号裸起步**：违反 ADR-0003（顶层强制 `schema_version`），
  后续破坏性变更失去迁移判定起点，否决。

## 后果

- 正向：新 schema 从第一版起即受迁移链纪律约束（红线 6 落地）；
  版本缺失=按 v1 的规则使"未来版本拒绝加载"（防旧版本游戏用旧 schema
  覆盖新存档）从第一天起可单测；旧档作废边界清晰，无双重语义维护成本。
- 代价：v0.1.x 玩家档不可继承（一次性弃迁）；旧档进入新版会被拒载
  （错误可读、磁盘原档保留，供人工处置）。

## 相关决策映射

- architecture-100 §9.3 破坏性变更纪律（schema_version=1 起步 / 旧档不兼容 /
  未来版本才承担迁移义务）
- ADR-0003（迁移链：缺失=按 v1、只升不降、禁跳步、未来版本拒绝加载）
- ADR-0005（三保险 + 双缓冲；schema v1 重置一次后不再重置）
- decisions-100 §〇（旧实现作废）
