# 0005. 存档三保险与文件级双缓冲

日期：2026-09-07 / 状态：accepted

## 背景

实时流淌制（~10s=1 周）下存档时机是体验与安全的平衡题：存太频繁有 IO 压力，
存太稀玩家一次崩溃丢几十分钟进度。Web/移动端还有三个特有风险——刷新即丢内存态、
切后台可能被系统回收、iOS `visibilitychange` 时机不可靠。脚手架期已有
`SaveSystem` autoload（唯一写入口）与 `SaveMigrator` 迁移链（ADR-0003），
但"何时存、怎么写"未定型。

## 决策

1. **三保险时机**（GW5）：
   - **周界自动存**——周结管线末步（第 11 步），也是全模拟唯一写盘点；
   - **退出/切后台**——离开 GAME 前与 `NOTIFICATION_APPLICATION_PAUSED` /
     Web visibilitychange 触发；
   - **手动**——`request_save(reason)` 命令统一入口，reason 仅作埋点不分支。
2. **文件级双缓冲**：写 tmp → 校验（解析成功）→ 原子换名 → 保留 `.bak` 上一代。
   双缓冲是唯一写路径，损坏注入回退有专门单测；`.bak` 不露 UI（C28）。
3. **全量快照**：`SnapshotCodec`（GameWorld↔存档字典唯一映射点）产全量档
   （<~100KB），不做增量/差分。
4. **schema v1 重置一次**：重置时点=科技树 v2 定稿后（字段冻结包由 PR5R 执行）；
   此后任何破坏性变更一律走 SaveMigrator 迁移链 + 单测（ADR-0003，不再重置）。

## 备选方案

- **每刻自动存**：刻=10s，IO 频率 ×10 收益却趋零（崩溃窗口本就 ≤1 周），拒绝。
- **双份全量轮换存档**：与 `.bak` 双缓冲等价但多一份磁盘占用，`.bak` 方案更简单。
- **Resource 序列化存档**：ADR-0003 已否决（无法迁移、可被注入对象）。
- **多槽存档**：黄级演进，`save_game(slot:=0)` 参数化已预留，MVP 单槽。

## 后果

- 正向：任一时刻崩溃最多丢"当前周"（≤10s）；坏档被 tmp→校验→回退结构性杜绝；
  三路径触发全部可单测（三保险断言，PR8）。
- 代价：移动端硬杀进程丢当前周（写入已知限制）；iOS 后台时机须真机验证；
  每次字段冻结包变更要同步 SnapshotCodec 与迁移链（约定成本）。
