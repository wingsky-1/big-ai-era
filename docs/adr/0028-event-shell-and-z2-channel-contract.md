# 0028. 事件壳与 z2 弹层调度契约（决策级事件卡 P0 切片）

日期：2026-09-10 / 状态：accepted

## 背景

v1.0.0 试玩闭环（批7.3，#190）后浏览器实测暴露「z2 通道无事件面」：
活跃代码无事件系统（events.json/EventEngine 均随 #117 蓝图重构归档），
决策卡仅有 ModalScheduler 纯逻辑座次，无 L2 数据面与渲染实体。OP-RND-01
（randomness-spec）要求 P0 事件卡走「rng.event 率门 → 决策级 z2 二选一 /
通知级 z3 toast」双通道；批7.4（#194）裁定为决策级单通道切片（通知级
z3 toast 无渲染面，事件触发行走周报对账兜底——规格允许"当周周报行兜底"）。

方案经独立对抗性评审（七条"必须改"全部采纳），本文档登记裁决与契约。

## 决策

### D1: 事件触发模型——率门 + 确定性轮转（否决归档 EventEngine 全量复活）

- 周结 phase11（WeeklyPipeline 尾部）判定：`EventShell.roll_week()`——
  决策在位=顺延（跳过率门，rng 流位置不前进）；无 pending 才消费
  `rng.event` 域 `hit_domain("event", rnd_event_rate)`；命中→轮转取卡置
  pending。单周至多 1 张。
- **确定性轮转**：文案池不做随机取句（randomness-spec C.3 纪律）——取
  「已见频次最小的卡（同频=表序首个）」；游标存 `已见计数集合` 而非裸索引
  （对表序变更免疫；P1 插卡零迁移）。archive EventEngine 的谓词触发/
  冷却窗口/效果延迟消费不复活（P0 无需求方；将来加谓词=轮转池加过滤器，
  零返工）。
- 率门统计口径：在位顺延跳过判定使实际发卡率略低于 0.25 门（正常流即时
  处理差值趋零）；标定走离线万次模拟脚本，GUT 只做固定种子确定性断言。

### D2: 效果基准——静态绝对值 + 绝对区间护栏

- 事件金额=现实锚定事件的语义值（"横向课题到账 ¥15k"），**静态 amount**，
  非玩家状态百分比；护栏=events.json `_bounds` 绝对区间（cash
  [-10000, 20000] / influence [1, 10]）。
- "结算层收入波动 ≤±10%"口径属 `rng.task`（P1 任务波动壳），不适用事件卡
  （randomness-spec A.1 两行对照）——防"10% 分母是什么"的规格空洞。
- 效果类型面 P0=cash/influence/none 三型；share 卡（工期/质量修正）超出
  类面，整卡砍出卡组（texts 键保留=池超集，P1 扩类面上线）。
- 护栏加载期校验：形状非法/越界=该卡拒载，牌堆数越界/全卡非法=fail-fast
  空牌堆（push_error 留痕）；choices 长度护栏锁定 2（不为 N 选一留口）。
- **预览即承诺**：选项预览句与实际入账同源（同一 effect 对象下发），GUT
  断言渲染值==入账值（test_event_shell / test_z2_channel_flow）。

### D3: z2 调度——并行队列 + NAMING 显式入表

- 多 z2 源（决策/命名/周报）并行检测（`_active_z2_sources` 每帧即时计算），
  呈现序=ModalScheduler 秩：**DECISION(0) > NAMING(1) > REPORT(2)**
  （UNLOCK 3 / TOAST 4 保留）。REPORT 秩 1→2 为契约演进（既有断言随改）：
  决策=强迫处理即时性最强；周报=显著周对账主内容；命名=主动期待的收尾
  仪式，可容忍同帧排队。同优先级 FIFO（既有 push 稳定插入）。
- **消费循环单向流**：scheduler 语义由"活跃源即时计算+呈现位"承接——
  呈现中防重入（`_presenting` 单一位）；源清=处理完成；PanelStack 只管
  在屏互斥（z2 入栈，同层互斥/has_blocking_top 生效）。双记账切分：
  待弹序（源计算）≠ 在屏态（栈+host）。
- 决策卡交互闭环：选项按下→入账+结果句+确认钮出现（结果句不被一闪而过）→
  玩家确认→close_requested→收层→下一源呈现。命名保持"提交即清 pending
  自动收"（批7.3 语义）。周报=「知道了」确认收层。

### D4: 停流挂遮罩状态——与触发源解耦

- `z2_blocked = f(任意 z2 面板在屏 OR 任一 pending 源活跃)`——自动弹周报
  与灰点手开周报**同一停流语义**（同一面板双入口不双语义）；决策 pending
  即停（玩家未看到弹层的帧窗内世界也已停，防插队失真）。
- 灰点=z1 指示器（ReportDual.ingest 决策：显著+1x=自动弹请求 pop；其余=
  dot），点击开 z2 周报面板。z3 toast 实体 P0 不做（通知级事件无独立卡，
  对账行走周报兜底）。

### D5: phase11 补登记（ADR-0015 步序契约扩展）

- WeeklyPipeline phase 序追加 **11 事件判定**（7a-7d/8 周报/9 存档/10 广播
  之后）：管线只做「判定+置 pending」，**永不挂起等待 UI**——选择/入账/
  对账行发生在管线外 UI 回调时点。
- EVENT 对账行归属=选择发生时的当前累积周报（当周报告已弹出则随下周报告
  出现）——数据层先行、渲染顺序归调度，数据互不等待。

### D6: 解锁弹卡（UNLOCK_POPUP）渲染实体不建

- 现无解锁事件生产者（树 lit 无弹卡契约）——实体=零消费方死代码（A8 空
  壳禁令）。UnlockPopupLogic 纯逻辑与 scheduler 座次保留，生产契约落地时
  （GDD 变更）再配实体。

### D7: 存档域

- events 域（12 域清单既有键）落 `{"pending_id", "seen_counts"}`——决策
  pending 跨会话恢复（Web 刷新/崩溃后 z2 重弹）；旧档无域=空游标初始态
  （开放容器加键零迁移，SaveMigrator 豁免）。

## 备选方案

- **复活归档 EventEngine**（谓词+冷却+效果延迟消费全量）：P0 无谓词需求方，
  适配废弃 API 的成本全在当下、轮转是真子集零返工——否决（D1）。
- **决策/命名同周单源互斥**：实现只有"丢弃命名 pending"（内容丢失）与
  "禁止决策期间产生命名"（管线被 UI 状态污染）两态，皆不可接受——否决，
  并行队列（D3）。
- **停流挂触发源**（自动弹停/手动开不停）：同一面板双语义、输入语义混乱
  ——否决，停流挂遮罩状态（D4）。
- **复用现有表扩键存事件**（rng.json/ui.json）：事件卡结构（id/多选项/
  效果对象/护栏）与现有表形状错配，必返工——否决，新建 events.json（D2）。
- **事件游标存裸索引**：表序变更（P1 插卡）旧档错位——否决，已见计数集合
  （D1/D7）。

## 后果

- 正向：试玩卡死面（世界停流画面无响应）消除；事件内容零新 RNG、文案池
  确定性可复现；z2 通道从单源特化变为多源通用调度。
- 代价：main 消费循环复杂化（presenting/源计算/灰点三态）；phase11 使
  周结步序 +1（步序表随 ADR-0015 补登记维护）。
- 后续：P1 事件面扩类（工期/质量修正、supply_discount）与通知级 toast
  实体按同类模式增量；万周率门标定脚本归 nightly。
