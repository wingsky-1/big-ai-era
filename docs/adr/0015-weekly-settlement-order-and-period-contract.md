# 0015. 周结管线的收入结算与破产判定步序契约

日期：2026-09-08 / 状态：accepted / 落 DR-031（C1、B-2、D-11、R1、R2）与 issue #72（批 1a）

## 背景

周结管线存在三处结构性缺陷，彼此咬合：

1. **D-11 周报收支裂缝（双侧）**：World 侧 `ledger` 在任务过账**之前**抓取 →
   `report.money_row.income` 不含 `task_reward`，而 `cum_income` 含；UI 侧
   `main.gd` 传 `get_resource_view()`（**无 `rows` 键**）→ 周报恒显兜底文案
   "本周运转平稳"，收支行根本不可见。
2. **B-2 破产判定步序**：破产短路在任务结算**之前** → 本周有任务结算仍会被判破产冻结。
3. **R1 账期归属无契约**：`_week_revenue/_week_expense` 是"自上次 `accrue_week`
   以来的累计"，而买卡/研究/入队/事件等**非周结过账**都经 `apply_delta` 累加 →
   周报收支行不闭合、净流入预告无法定义。
4. **R2 确定性真源受损**：收入脉冲使用 `RandomNumberGenerator`（ADR-0008 明令禁止的
   第 4 个随机消费点），且读档时 `rival_track.setup` 多消费 4 次 jitter 后又被存档值覆盖。

C1（收入口径改占槽任务结算）是 C2（事件闸）/ 1g（呈现层预告）/ 2（任务池联标）的
共同前提：事件闸值以"经营收入"为基准，脉冲口径下自动合规（4.9%），先做闸即白标。

## 决策

**① 步序固定为**：

```
1 卡时预算重置 → 经营收入结算（占槽任务过账 + cum_income 累计）
  → 固定支出（工资 × 在册人数）
2 收支 ledger 快照（已含 task_reward）
3 破产判定短路（在全部经营收入结算之后）
4 账期翻页（reset_week_ledger）
5 delayed 效果消费 → 出分/SOTA → 竞对 → 迷雾 → 灵感/事件 → 阶段 → 周报 → 自动存档
```

**② 账期契约**：`ledger` 只统计"本次周结步序 1–3 期间"的过账；**非周结过账**
（买卡/研究/入队/事件 immediate）计入**当前未结算周**，在周结时一次性入账，
随后由 `reset_week_ledger()` 翻页。周报 `income − expense == net` **恒成立**。

**③ 破产判定写死在"全部经营收入结算之后"**（修订 DR-021 B3 的"收支后"措辞：
"收支"的内涵扩展为"工资 + 固定支出 + 任务结算"）。

**④ 周报载荷新增 `rows`**（TextService 模板渲染），`GameWorld.get_last_report()`
是周报 UI 的**唯一数据源**（修 UI 侧断裂）。

**⑤ 确定性收口**：脉冲源退役时**删除** `_DeterministicRoll` 与 `_income_roll_seed`
（不保留隐性第 4 消费点）；RNG 消费点回到 3 处且全部经 `RngStream` 域。
读档路径 `rival_track.setup(..., consume_rng=false)`——不重抽 jitter，
用存档的 `action_actual_weeks`，消除 D3 的序列漂移。

## 理由

1. **周报闭合口径天然成立**：`ledger` 与任务过账同处步序 1，报告无需二次拼装。
2. **破产语义最直观**：判定"看到本周全部经营收入"，与净流入预告口径一致。
3. **账期契约零代码改动即可定义预告**：非周结过账的归属唯一（下一个未结算周）。
4. **确定性是区间断言的唯一地基**：V6/V10/V1 分位数、竞对 ε、nightly 蒙卡都依赖
   同 seed 可复现；读档回放一致性用例（`test_same_seed_replay_after_load`）是其兜底。

## 备选方案

- **短路后移（备选，未选）**：任务结算保持原位、破产判定移到其后。两者在"周报闭合"
  上等价，但语义不同（破产时已执行任务结算），且 GDD §5.2 管线图改动更大。
- **双 ledger（否决）**：周结账 + 实时账并存 → 改动面大、UI 双口径易错。
- **保留 `_income_roll_seed` 并补 restore（否决）**：脉冲源已退役，保留字段等于
  给第 4 消费点留后门；ADR-0008 要求消费点登记可 grep 验证。

## 后果

**正向**：周报收支闭合且真实渲染、破产判定口径清晰、账期可复算、净流入预告可定义、
确定性真源恢复（消费点 3 处）。

**代价**：
- 无任务结算时纯模拟会破产（测试需注入任务流：`AutoTaskPolicy`）；
- GDD §5.2 管线图与 ADR-0005 的"周结末步"映射需同步更新；
- 破产时已结算的任务收入会进入终局档（语义变化，需在试玩验收中确认）。
