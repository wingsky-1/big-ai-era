# 0007. 事件阻塞语义与决策卡 pending 入档

日期：2026-09-07 / 状态：accepted

## 背景

事件形态=实时插入式（决策卡阻塞/通知 toast 分级）。若决策卡不阻塞模拟，
玩家读选项期间周结继续跑，选项效果的前提状态已漂移，"预告=结算逐项一致"
验收不可成立；若 pending 不入档，读档丢卡，同样撕裂预告一致性。
事件若不只在结算点产出，刻级高频评估会让概率断言与调参不可控。

## 决策

1. **只在结算点产出**：EventEngine 仅在周结管线第 9 步消费 `rng.event_roll()`
   评估；刻结算零事件逻辑。
2. **决策卡阻塞**：抽中决策卡 → `blocked_by_card=true`（paused 双源之一，
   ADR-0006）→ 前置不变式"pending 非空不结周"（带卡不结周）。
3. **pending 入档**：结构 `{event_id, shown_options, applied_effects,
   week_due}` 全量入档——读档还原后选项预告与已应用效果可对账。
4. **稍后处理**：仅 UI 收起，阻塞不变；本周结前强制选择（周结前拦截断言）。
5. **同周双卡消费规则**：每周至多 1 张决策卡（notice 不占额）；灵感与事件同周
   命中且事件抽中决策卡 → `week_due=下周` 顺延，确定性入档。
6. **paused 四不变式**：唯一源（双源 OR）/效果原子应用/同帧禁重入/幂等回滚；
   效果应用后补一次解锁重评。触碰训练状态机的效果一律 `timing=delayed`
   （下周结第 3 步 pre-settle 消费）。
7. **预告=结算逐项一致**为验收硬标准（决策卡三态单测+读档还原断言）。

## 备选方案

- **不阻塞、错过可背面点击**：流淌中状态漂移使预告失真，验收不可行，拒绝。
- **倒计时自动选择**：施压设计，与"同屏待决 ≤1、周必做 ≤1"宪法冲突，
  DR-012 明确不进 MVP（倒计时决策=不进清单）。
- **pending 不入档**：读档丢卡，预告断裂，拒绝。
- **搁置待办（跨周处理）**：v0.2 复议项，暂不放开。

## 后果

- 正向：决策卡全程可回放可验收；读档还原零丢失；事件概率（权重分位数断言）
  与周结管线序对账闭合。
- 代价：UI 需三态管理（阻塞/收起/已答）+同帧串行序（决策卡先于周报，按信号
  到达序）；`week_due` 顺延使 pending 结构含时序字段，schema 冻结包须含之
  （PR5R）；跨周搁置留作 v0.2 复议。
