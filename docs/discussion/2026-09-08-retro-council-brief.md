## 二、冻结口径（提案若越界直接判黄红）

1. **玩法裁决不翻案**：DR-001~029 的机制裁决维持；本次产出只改"如何把裁决兑现成可实施的 issue"。
2. **verify.sh 全绿红线不松**：不废既有门禁，只做增量（视觉快照/对账断言等）。
3. **GitHub 唯一事实源不变**（gd-issue-pipeline §0.5）；改的是 issue 内容质量标准。
4. **架构分层 L0–L4 / RefCounted / apply_delta 唯一写点 / RNG 三消费点**：架构纪律不动。
5. **[change] 双签**：触及已冻结范围（如新门禁进 verify.sh 必跑集）须制作人批准。
6. 数值问题一律"给推演"，本次不裁任何数值。

## 三、议题包（四席各领，独立提案、互不共享草稿）

> 每席输出：①根因分析（逐条引事实底料 F1–F7）②流程改进提案（逐条标 DR 依据+黄绿红评级）③本席可承诺的交付物清单（文件/模板/断言/检查单级别）④每议题 2 个开放问题回主持人。总长 ≤900 字/席。

- **主持人议题 0（已裁）**：确认根因主轴——"验收点体系空心化"：issue 没有可勾验收点 → 实施 agent 无目标规格 → 自验证变成"跑通现有测试"而非"对照规格"→ 规格缺口全部流入真人试玩。
