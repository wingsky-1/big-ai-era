## 一、六机制（评审修订已内嵌，标 ⚖）

**① 规格翻译**
- 排期提交物=issue 清单+DR→issue 清点对账（漏裁决=排期未完成）。⚖M4：映射**不挂 decision-log 尾部**（每次裁 DR 都回改冻结文档，成本高）；改为**建 issue 前对 decision-log 做一次性清点**（清点产物附排期提交物）。
- **验收锚前移**：DR 立裁时直接写验收句；DR 条目标验证状态两级（已试玩验证/仅稿面裁决）。⚖m4：存量 DR 补录=编辑 decision-log，**标 [change] 待制作人批准**（列入待批项 B）。
- issue 双检：形式检查（脚本化）+内容评审。⚖M4：独立子代理对抗评审**降为 L 规模 issue 抽检**（S/M 规模走形式检查+主策划内容审），防会话成本翻倍。
- 验收粒度：每功能点 ≥3 条 checkbox（正常+边界/空态+可观察终态；[T]注 GUT 用例名/[P]注试玩脚本）。

**② 实施对账**
- 完工 DoD=逐条验收点自证，证据只可引用不可复述。⚖m1：勾选行须附**该用例的 GUT passing 输出行**（测试名存在≠通过≠覆盖）。
- 三方对账断言（面板/键名/信号）。⚖B1（Blocker）：**放弃场景路径自动推导**（实测 11 个 PanelId 仅 4 个可命中 snake_case 推导，PAUSE_MENU 正是 #67 无 tscn）——改为 **PanelStack 注册表加显式 scene_path 字段单点声明**，对账只验"声明↔tscn 文件存在↔match 分支存在"，零推导零豁免表。⚖S4 终裁补丁（已核 panel_stack.gd:24-37+全库 grep：DASHBOARD=概念席位不入栈、TASK_MGMT=预留、两者零调用面）：**对账集合=注册表中被 push_panel 调用面引用的 PanelId**——被引用者三方对账；未被引用者断言"确无调用且无场景"（预留席位的正确不变式）；零推导维持，仅分开定义"对账集合"与"注册表全集"。⚖m3：同一 issue 内把 presenter↔view 共享键**收进单点常量源**（治本键名失配，非只抓现行）。
- selftest 扩场景必须挂靠某条 issue 验收点；信标落地与 S6 硬化同一 PR。

**③ 试玩闭环**
- ⚖B3（依赖倒置修正）：**反馈固定表单 issue 化列入首批沉淀动作**（影子熔断的统计前提，先有结构化数据才校准得了阈值）。
- 修完必答"用户原话被哪条新增验收点捕获"。
- **停线复盘**（原"不可玩熔断"，⚖M1 改名与 skill §5 blocked-human 熔断区分）：同类反馈≥2 条或核心循环阻断 1 条→停线 24h 复盘出修复 issue 方可恢复；先影子模式（只记录不拦截，跑满 1 批校准）。⚖m2：**判定与宣告权=制作人席**（无常驻主持人，归属必须唯一）。
- 停线复盘会上允许对"仅稿面裁决"的 DR 轻度复议（有门槛、一次一议、须试玩证据）。

**④ 反馈沉淀**
- 每批试玩复盘必含"模板增删+流程水位"合并节（⚖M4 两仪式合一）：字段说不出"防哪条已发生缺陷"即删；连续 2 里程碑零反哺自动降可选。
- 设计债登记：GDD 附录登记销账制。

**⑤ 度量回顾**
- 里程碑三行式+第 4 行"流程漂移"（逃逸缺陷环比上升=稀释报警）+过时文档清单（当期修）+模板字段命中率。

**⑥ 流程硬件**
- **无 issue 不合码**。⚖B2（Blocker）：强制执行点=**issue-gate check**（CI 解析 PR body 的 issue 引用→校验关联 issue 过 lint）+**制作人一次性配置分支保护**（require issue-gate）——两者均列入沉淀交付物与行动项，否则该红线与它批判的"规范无检查点"同构。
- `scripts/issue_lint.sh`。⚖M2：首版**只卡两条硬规则**（checkbox≥3+[T]/[P] 标注格式，最低误报）；触发时机=PR 关联 issue 校验；内容质量（边界态/终态是否真成立）归子代理抽检与主策划内容审，不归脚本。
- 流程真源=docs/standards/，skill 文件只留索引与行为红线（⚖M1 收口双头管辖：issue 模板真源=standards/issue-spec.md，gd-issue-pipeline §2.1 改为引用；新增交付物"gd-issue-pipeline 修订"）；流程文件经 AGENTS.md 常驻注入生效；里程碑 handoff 附流程水位段。
