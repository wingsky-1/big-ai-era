# v0.1.5 开发驱动 Prompt（主程序席 · 协调子 agent）

> **用途**：复制本文件「§八 可复制 Prompt」段落，直接发送给新会话的**主程序席 agent**，即可驱动 v0.1.5（13 单）的开发实施与子 agent 协调。
> **配套真源**：`handoffs/2026-09-08-decision-to-015-dev-handoff.md`（交接）→ 本 Prompt（执行）→ issue（DoD）。

## 一、设计说明（给人类看，不随 Prompt 复制）

本 Prompt 的设计目标有四条：

1. **不可乱序**：v0.1.5 是"数值地基 + 核心修复"，五张 p0 单（#71/#72/#73/#76/#80）互为前提；乱序会重演"先标定后改口径"的返工（本会话已撤销过一次调表方案）。
2. **不可降级**：每张 issue 的验收点即 DoD；agent 常见失败模式是"把验收点改写成更容易实现的版本"——Prompt 用"不得自行降级 + 自证表只引用不复述"卡住。
3. **可并行但要可控**：13 单中 4 张可并行（#67/#78/#79/#81），其余必须串行；Prompt 给出分派模板，避免"一句话派活"导致子 agent 自由发挥。
4. **有明确的停手线**：复议项（θ/k 阶段化、V6 占比、18 节点扩树、N6 双签）**未齐材料不动工**；Prompt 显式列出，防止 agent"顺手做了"。

## 三、子 agent 分派模板（主程序席必须按此格式派活）

```markdown
【任务】实施 GitHub issue #<N>「<标题>」
【仓库】/home/tangyi/dev/game/big-ai-era（分支：feat/<N>-<slug>）
【DoD】逐字复制 issue 的验收点（≥3 [T] + [P]），不得增删改
【改动面】<架构复审 §5 给出的文件清单>
【硬约束】<与本单相关的 1–3 条，从 handoff §三 摘>
【验证】bash scripts/verify.sh 全绿；新增断言须列出用例名与断言点
【交付】PR（body 引用 #<N>）+ 自证表（证据只引用不复述 + GUT passing 行）+ issue 验收点勾选
【禁止】改 issue 验收点 / 跳过 verify / 顺手做复议项 / 引入新依赖
```

**分派判据**：单的依赖全部已合并 ∧ 改动面不重叠 ∧ 不触碰同一数据键 → 可并行；否则串行。

## 四、每单闭环（五步，缺一不可）

1. **读**：issue 验收点 + 架构复审对应节 + 需求文档对应模块（功能点编号一一对照）；
2. **做**：按红线实施（分层单向 / RefCounted / 数值进 `src/data/` / autoload 禁 `class_name` / 破坏性存档走 SaveMigrator）；
3. **验**：`bash scripts/verify.sh` **本地全绿**（同一命令即 CI）；
4. **证**：自证表——每行格式「验收点 → 实现证据（`文件:行号`）→ GUT 用例名 → passing」；
5. **报**：PR + issue 勾选 + 四行阶段汇报。

---

## 五、四行阶段汇报格式

```
批次：P<N>（#<单号列表>）
verify：<全绿 / 失败项>
断言：新增 <n> [T] / 勾选 <m> [P]
风险：<偏差或"无">
```

## 六、阻塞处理

| 情形 | 动作 |
|---|---|
| 验收点与实现冲突（如验收点要求的行为会破坏另一条红线） | **停手**，标 `blocked-human`，写清「冲突点 + 两条依据 + 建议选项」，等制作人裁决 |
| 数值算不出来 / 与实算基线矛盾 | 停手，回到数据表复算，附计算过程；**不得猜** |
| 依赖单未合并 | 等待或改做可并行单；**不得先做下游** |
| 发现 issue 漏了边界态 | 在 PR 里补 `[T]`，并在 issue 评论说明；**不得静默放过** |
