## 全局约定（先读，各节不重复）

- **PanelStack 现状**（src/ui/panel_stack.gd PanelId 枚举）：z1 互斥栈（ROSTER/TECH_TREE/TASK_MGMT/REPORT_ARCHIVE/INTRO）+ z2 阻塞（DECISION_CARD/NAMING_DIALOG/GAME_OVER/PAUSE_MENU/AUTO_REPORT）+ z3 toast（同屏≤3、倒计时绑游戏时间、不入档）。本批新增面板 id（RETURN_SUMMARY/COLLECTION/RECRUIT_MARKET 等）实施时登记进枚举封闭集合，禁字符串 id。
- **挂载点惯例**（src/ui/main/main.tscn）：z1/z2 弹层挂 %ModalContainer；z0 主台四区=资源栏+%ResourceSubrow / %Workspace / %RivalTrack / %Dock；z3 toast 现为 %ToastLabel，规划形态为顶部横条队列。
- **遮罩规则沿 DR-020**：z1 遮罩点击一律关；z2 仅 PAUSE_MENU 遮罩可关，其余阻塞卡不关（强迫处理）；pop 动画锁+push 排队、同帧按信号到达序串行（决策卡先于周报）。
- **信标**：各节链路断言的信标断言名待回填（真源表同口径）；命名约定与 GUT 断言名建议见附录 D/E。
- **基准**：桌面 1280×720 与竖屏 375×667 双基准；21:9/4K 抽查（skill 适配规范）；竖屏折叠序=心智权重倒序，工作区永不折叠（DR-009/015）。
- **常显态总原则（反馈②教训）**：任何有状态切换的界面必须回答"失焦回来玩家怎么知道现在什么状态"——本稿每节"常显什么"栏即该问题的答案，实施时该栏元素不得以"动画里顺带表现"替代。
- **与真源表 §2 既有 5 行的关系**：V1-03/V1-04 与 §2 既有"员工 idle/assigned"行、"user_paused"行同源——既有行是 v0.1.3 缺陷修复验收行（已作 PR-γ 验收点），V1 行是 v1.0 规划行（收敛同口径并补 N7 标注）；两行**并存不互斥**，实施 PR合并核对、信标共用，待 PR-γ 落地后由维护纪律统一收敛（删行留痕）。其余 V1 行均无 §2 对应，属纯新增。

### V1-01 归来摘要弹层（D-2 · 批1 · **N1 漏译待建**，原草案第 15 条未落 issue）
- **信息架构三问**：主信息=钱还好吗（回来第一问）；可隐藏=大事区细节（竖屏可收折，桌面全展）；可交互清单=待办跳转、关闭。
- **哪屏**：z1 常规层（不阻塞流淌，遮罩可关）挂 %ModalContainer；新 PanelId.RETURN_SUMMARY 进枚举；不进 tick_feeding 门控（世界照走）。
- **哪键**：自动弹出——读档/回局时由逻辑层比较存档时间戳差≥阈值后发 session_resumed 信号推入（信号待建，D-2 属 v0.2 第一批）；无手动入口键，Dock 不加键。
- **点击后出现什么**：三分组纵排（VBoxContainer，禁坐标）——①"钱还好吗"区：现金+周净流入两行键 return_summary_money_cash / return_summary_money_flow；②"要我管的"区：待办行键 return_summary_todo_row（**只指向已存在待办，绝不创造新待办**——跳转键仅 router 语义，发"打开对应面板"信号，不直接改状态）；③"大事"区：上周显著事件行 return_summary_event_row（≥~5% 显著变化口径与自动周报一致）。
- **常显什么**：三分组全量常显（不折叠不省略）；待办区无待办时显空态键 return_summary_todo_empty；标题键 return_summary_title。
- **三态覆盖**（§1）：即时态=弹层推入动画+跳转键按下反馈；结果态=跳转后目标面板可见（z1 互斥替换本层）；禁止态=无禁用操作（只读弹层），"要我管的"区空=空态文案而非置灰。
- **链路断言**（§2）：读档→session_resumed→弹层推入（GUT assert_signal_emitted）；resources_changed→钱区刷新（复用 presenter 键）；跳转键→panel_pushed(RETURN_SUMMARY 退出+目标推入)。"1 提醒只指向已有待办"作为 GUT 断言项（摘要行集合⊆现存待办集合）。
- **空态**（§3）：无待办→return_summary_todo_empty（引导性文案，非空白）；无大事→return_summary_event_empty。
- **竖屏折叠 375×667**：三区纵排满宽；"大事"区可收折（心智权重：钱→要我管的→大事倒序折叠）；弹层非工作区组件，可整层收为顶部摘要条（点开重展）。
- **触屏 ≥48px清单**：关闭键、每个待办跳转行（整行可点）、大事区收折头。

### V1-02 引导锚定气泡（D-3/D-5 · 批1 · **N1 漏译待建**，随批1 文案管线）
- **信息架构三问**：主信息=下一步该做什么（一步一事）；可隐藏=无（气泡必须可见，但可随手关）；可交互清单=随手关（唯一）。
- **哪屏**：z3 顶层浮层（不阻塞不入档），锚定气泡节点挂主台锚点层（随目标元素 Container 锚定，禁固定坐标）；失败教学一次只弹一条。
- **哪键**：无入口键——tutorial step 推进（tutorial_step_advanced，D-1 flags 持久化）驱动；自动出现、自动迁移。
- **点击后出现什么**：气泡=标题 guide_bubble_step_N + 正文 guide_bubble_body_N + 步骤序点（guide_bubble_dots）+ 随手关键（✕，guide_bubble_dismiss）；N=步骤号（键名以 texts.json 实录为准，实施时按 D-3 文案批登记）。
- **常显什么**：当前步气泡常显直到完成步或随手关；**关了世界照走**（绝不进停喂门控、不弹遮罩）。
- **三态覆盖**（§1）：即时态=随手关淡出反馈；结果态=步完成时气泡内容替换/消失+锚点迁移至下一步目标；禁止态=无禁用操作（同刻多步只显一条，其余静默排队不显示）。
- **链路断言**（§2）：step 推进信号→气泡内容刷新（GUT 调 presenter 断言视图键）；once 单发（重复触发不重复弹）；读档还原（flags.step/done 恢复后气泡与进度一致）；零操作不卡死（超时降级为手记可查，不阻塞流淌）。验收对齐 DR-029：[P] 10 秒首指派、4x 挂 10 周回来 10 秒说清 3 件事。
- **空态**（§3）：全部步完成→气泡系统整体不再出现（终态即"无引导"，非空白气泡）；二周目 meta.cfg 豁免（教学不弹，送"博导手记·往年卷"属 v0.2 后期 D-4，本批只留豁免开关）。
- **竖屏折叠 375×667**：气泡锚点随目标元素折叠位重算；文本满宽换行不截断；气泡宽≤屏宽-2×页边距，禁止横向滚动。
- **触屏 ≥48px清单**：随手关键、气泡本体（点气泡=不推进不关闭，仅确认可见；推进靠真实操作，避免误触跳步）。

### V1-03 员工实体卡（反馈③升级形态 · **N7 后半** · PR-γ 承载）
- **信息架构三问**：主信息=几个人、各自在干嘛；可隐藏=训练进度细节（折叠态省略，展开可见）；可交互清单=选中卡、指派。
- **哪屏**：z0 主台 %Workspace 内常驻组件（非弹层）；竖屏折叠为横滑行或紧凑网格，工作区本体永不折叠。
- **哪键**：无入口弹层——卡片本身即入口：点卡 1 次选中、再点任务槽或指派键完成指派（2 次点击内完成指派，验收 [P]）；长按/悬停出详情提示。
- **点击后出现什么**：卡片元素=员工名（staff_card_name）/状态字样（staff_card_status_idle/assigned/training）/在岗任务名（staff_card_task_name）/训练进度条（刻级）；选中态描边（主题资源，不散落覆盖）。
- **常显什么**：卡组常显（失焦回来第一眼可见"几个人、在干嘛"）；指派后 0.5s内刷新（GUT 锁）；未招满时占位卡 staff_slot_empty（空态非空白，提示招聘去向）。
- **三态覆盖**（§1）：即时态=卡片按下反馈；结果态=状态字样翻新+任务槽联动刷新；禁止态=无 idle 目标或员工在岗时指派入口置灰+原因可查（staff_assign_disabled_reason，悬停/长按提示）。
- **链路断言**（§2）：assign/unassign→resources_changed→卡 0.5s刷新（沿验收条 test_staff_assign_signals）；presenter↔view 键走共享常量单点（DR-030 m3，禁裸字符串）。
- **空态**（§3）：零员工开局→staff_roster_empty 全宽占位卡+引导（指向招聘/开局赠送说明，不弹层）。
- **竖屏折叠 375×667**：折叠为横滑行或紧凑网格（触屏≥48px），卡内纵向压缩（名+状态两行）；工作区永不折叠（DR-009/015）。
- **触屏 ≥48px清单**：每张卡整卡、指派键、占位卡。

### V1-04 流速/暂停常显态标识（反馈② · **N7 前半** · PR-γ 承载）
- **信息架构三问**：主信息=现在流速/暂停态（失焦回来的第一答案）；可隐藏=无——常显就是本功能点的存在意义；可交互清单=暂停/档位键（既有，本点不加键）。
- **哪屏**：z0 主台资源栏副行（%ResourceSubrow）常驻组件；遮罩与任意弹层之上可辨（层级高于遮罩，z2 打开时仍可见）。
- **哪键**：无新键——沿用现有 %SpeedPauseBtn/%Speed1xBtn/%Speed2xBtn/%Speed4xBtn；本功能点是"状态可见性"非新交互。
- **点击后出现什么**：不出现新弹层；按键后常显标识即时翻新（文本+图形双通道）：已暂停=pause_badge（图形▶/‖+文本"已暂停"）、自动暂停=auto_pause_badge（区别色+文本"自动暂停"）、流速档=speed_badge_1x/2x/4x。
- **常显什么**：**失焦回来的核心答案**——当前档位文本+图形常显；用户暂停与 z2 自动暂停两种标识区别常显（映射表 §2 前三行+V1-04 同源）。
- **三态覆盖**（§1）：即时态=播放/暂停/档位键按下反馈；结果态=常显标识翻新（10 秒内可辨，验收 [P]）；禁止态=z2 阻塞期间流速档键置灰+原因（decision_wait_reason，"决策等待中"）。
- **链路断言**（§2）：set_paused/set_speed→常显标识翻新；tick_feeding_gate_changed→自动暂停标识；selftest_web 信标断言（S9 口径：任意失焦/遮罩后 10 秒内可辨识流速与暂停态）。
- **空态**（§3）：不适用（常驻组件无空态）；BOOT 未进 GAME 前不渲染。
- **竖屏折叠 375×667**：资源栏副行位显示（映射表既有行口径）；标识紧凑化但文本不省（双通道至少文本保留）。
- **触屏 ≥48px清单**：四个档位/暂停键（既有键触屏复走查）。

### V1-05 多任务槽任务卡（**N6 多任务槽设计稿1** ·【change】未双签 · 反馈④a 圆桌裁决项）
- **信息架构三问**：主信息=当前任务与进度；可隐藏=队列深度细节（折叠态省略）；可交互清单=选槽、指派。
- **哪屏**：z0 主台 %Workspace 内常驻组件；槽数与形态**依 N6 多任务槽设计稿定**（docs/discussion/2026-09-08-mech-design-drafts-v1.md 设计稿1；【change】未双签——未双签不出现在任何批次，本节仅预写形态）。

- **哪键**：无弹层入口——槽卡即入口（点槽选中→点 idle 员工卡指派，与 V1-03 双向操作）；队首完成自动顶入（真空三件套①，任务排队预填）。

- **常显什么**：全部槽卡常显；进度刻级常显；队列深度指示（task_queue_depth，"排了几个"）常显于槽组头。
- **三态覆盖**（§1）：即时态=槽卡按下反馈+指派成功卡内刷新；结果态=完成顶入动画+新队首就位；禁止态=槽位锁定或无 idle 员工时指派入口置灰+原因（task_slot_locked_reason）。
- **链路断言**（§2）：task_queue_changed（待建）→槽卡列表刷新；progress_ticked→队首进度条刻级；完成→顶入动画+resources_changed 联动。
- **空态**（§3）：全部槽空→task_queue_empty 引导（指向可接任务来源，非空白）。
- **竖屏折叠 375×667**：**工作区永不折叠**（本组件属工作区）；卡内纵向压缩、进度条满宽；槽组纵向滚动（工作区内部滚动，非折叠）。
- **触屏 ≥48px清单**：每张槽卡整卡、指派入口。

## 【下游省工自问】

1. **实施者会先问：键名到底叫什么？** 本稿所有 texts/data 键名为提案风格（snake_case 沿 texts.json 现例），实施 PR 登记键时如与文案席产出冲突，以文案批为准并回填本稿——不要自己发明第二套。
2. **"待建"信号谁发？** 本稿只声明 UI 期待什么信号，不定义逻辑层何时发；实施前逻辑席须在对应 issue 确认信号名与载荷（尤其 session_resumed/task_queue_changed/deploy_state_changed），UI 席不改逻辑层。
3. **V1-05 依 N6 设计稿（【change】未双签）、V1-08 依 N2 设计稿+开放问题③、V1-10 考工依开放问题②/Q5——依赖未闭合的节能先做吗？** 不能；拍板顺序=先裁节内标【待拍板】项（N6 还需先过 [change] 双签），再建 issue，避免返工。表行已按"行照出+标注待裁"处理，验收以拍板后口径为准。
4. **面板 id 进枚举时谁改 PanelStack？** 新 PanelId 登记是 L3 改动，随对应实施 PR 一次完成（枚举+场景挂载+GUT），禁止先改枚举留空壳（"注册未实现"类缺陷正是真源表 §1 封堵对象）。
5. **z2 卡弹序若同帧撞车（危机+融资+周报）怎么办？** 沿既有规则：信号到达序串行、决策卡先于周报；同帧多 z2 的顺序用例在扩容时必须补 GUT（本稿 V1-12 已列）。
6. **竖屏下 z2 卡会不会盖住常显标识？** V1-04 标识层级高于遮罩是硬要求；移动走查时若发现被盖，改层级不改口径（常显态是反馈②教训的封堵线）。
7. **彩蛋层"零效果"怎么验收？** V1-07 已给 GUT 口径（渲染不改 stats 键值）；不要顺手给年报加"看完送资源"之类的自嗨。
8. **信标断言名何时不再是"待回填"？** selftest_web 落地该界面时按附录 D 约定回填真源表；表列 lint 豁免仅限回填前，实施 PR 必须带信标。
9. **V1-15 为什么不做面板？** 已在节内给信息架构三问答案（单状态一眼即答，面板藏状态）；若 producer/主程序拍板要面板，改本节不改真源表行（行已覆盖两种形态的常显/禁用列）。
10. **V1-16 的"目标带"数值哪来？** 计数器值由逻辑层 flags（freedom_*）累加，目标带属数值稿收口项——未收口前显示"目标待标定"后缀；实施单不得自造目标值（数值硬约束归数值席）。
11. **V1-17 的吐槽文本谁供给？** F1 池键归内容席文本管线（DR-029 A-8），UI 席只定义"确定性轮转+空池置灰"的通道行为；实施时若池未就绪，按 texts 断链分支处理（键名占位+error），不得先塞裸串。
